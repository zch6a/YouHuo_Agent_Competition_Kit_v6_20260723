## 7. 首轮测试发现并修复的问题

### 7.1 提醒意图被医学名词覆盖

原行为：“提醒我下周去医院复诊”可能因“医院/复诊”被识别为挂号。  
修复：显式提醒、日历、待办等动作优先于医学领域名词。

### 7.2 冲突候选丢失任务域

原行为：“确认办理缴费”主要返回`confirm`，不利于生成具体账单澄清。  
修复：任务域优先于通用确认动作；确认/取消冲突仍强制澄清。

### 7.3 可信与不可信同名字段冲突

原行为：同一金额同时有可信工具事实和冲突OCR事实时，策略使用“存在任一可信来源”的聚合方式，存在继续放行风险。  
修复：分别追踪可信值与不可信值；关键字段值冲突时剥离字段、缺失必需参数并返回澄清。若OCR与权威值完全一致，只把OCR视为佐证。

新增两个单元回归测试和100,000项安全预演性质断言覆盖该问题。

### 7.4 烟雾测试的版本假设

原测试假设第一次保存交互档案必定得到版本2，但默认档案可能未持久化，第一次保存合法版本为1。  
修复：测试改为验证版本合法且实际配置字段正确，不再把实现细节当业务不变量。

### 9.2 修复的阻断性问题

1. **发布包中文文件名解码错误**：`competition_materials/` 下6个文件在Windows解压时按GBK解码，其中03、04、06三个文件根本没有落盘，`test_package_contracts_v3.py` 因此失败。已按UTF-8重新提取全部6个文件并删除乱码副本。

### 9.4 逐功能验收与两个复验可信度缺陷

新增 `backend/scripts/verify_features_v6.py`（配套 `run_feature_audit.py` 负责起停干净实例），对全部能力逐条做端到端断言，并强制校验 OpenAPI 覆盖率：任何没被实际调用过的操作直接判失败。已接入 `verify_all`；当前为 **122/122 通过，99/99 操作全覆盖**（该节写作时是 105/105 与 97/97）。

审核过程中发现并修复两个真实缺陷：

1. **账单已缴清时报告"已完成"**（`engine.py`）。查不到未缴账单时任务被标记为 `COMPLETED` 并播报完成，但什么都没执行——正是本项目明令禁止的假成功。现在区分"已缴清"（`DUPLICATE_BLOCKED`，播报"已经缴过了"）与"没有这笔账单"（`OK`），任务一律安全取消而非完成。
2. **复验脚本没有真正清库**（`verify_all.*` / `verify_heavy.*` / `check_artifacts_v6.py`）。SQLite 处于 WAL 模式，只删 `.db` 会留下 4MB 的 `-wal`：上一轮数据被重放回"干净"库，同时审计密钥已被删除，导致 HMAC 链校验必然失败；`no_runtime_database` 检查也可能在发布包里带着 WAL 的情况下通过。四处清理和交付物检查均已补上 `-wal`/`-shm`，`.gitignore`/`.dockerignore` 同步。

另有若干条最初判为失败、核实后确认是**正确安全行为**，已改写为正向断言：自动工具步骤禁止人工推进、未登记设备拒绝同步、高敏感字段仅在 `base_version == current_version` 时才允许合并、定位精度不足时抑制报警（701m 越界 + 20m 精度会报警，同样距离 + 3000m 精度只警告）。

### 9.5 语音自然度

反馈"语音过于机器化"。定位后发现主因不是合成引擎，而是**喂给引擎的文本**：`2026-08-09 14:00`、`126.50元`、`2026-07` 会被读成"二零二六杠零八杠零九 一四比零零"，换任何神经网络音色都救不了，老人也听不懂。

新增 `backend/static/speech.js`（零依赖，不破坏离线免密钥承诺）：

| 措施 | 效果 |
|---|---|
| 朗读文本规范化 | `2026-08-09 14:00` → 八月九日下午两点；`126.50元` → 一百二十六块五毛；今年的日期省略年份 |
| 择优选音 | 从 `getVoices()` 中优先挑选 Natural/Neural 类中文音色，而不是用系统默认的那个最生硬的 |
| 分句朗读 | 按标点切句、句间留 140–320ms 停顿，去掉"一口气念完"的机关枪感 |
| 可打断 | 每轮返回 cancel 句柄，新一轮发言立即停止上一轮 |

`backend/scripts/check_speech_text.mjs` 用引擎真实输出做 15 项断言并接入 `verify_all`，任何回退到机器格式的改动都会让构建失败。

顺带修了两处：`node --check` 按 CommonJS 解析，会**放过在 ES 模块下致命的重复顶层声明**（elder.js 改成 module 后立刻白屏）。已改为 `backend/scripts/check_browser_js.py`，按每个文件真实的加载方式（script / module）分别校验，并注入重复声明验证过它确实能抓到。

#### 离线神经语音（sherpa-onnx，可选）

在文本规范化之上接入了 [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx) 离线合成，架构与语言模型一致：**装了就用，没装就自动回落到浏览器语音**，绝不成为依赖。

- `backend/youhuo/tts.py`：懒加载 + 后台预热 + LRU 缓存；
- `GET /v6/speech/voice`、`POST /v6/speech/synthesize`（返回 WAV，需鉴权，文本上限 300 字）；
- 模型 `vits-melo-tts-zh_en` 约 160MB，**不随发布包分发**，`check_artifacts_v6.py` 新增 `no_bundled_tts_model` 强制校验；
- `sherpa-onnx` 不进 `requirements.txt`，离线免密钥承诺不变。

本机实测（CPU）：

| 场景 | 耗时 |
|---|---|
| 首句（含一次性模型加载） | 10.4s → **4.2s**（改为启动时后台预热） |
| 常规短句 | **0.94s** / 1.56s 音频（RTF≈0.6） |
| 命中缓存 | **24ms** |

过程中修掉三个真问题：

1. **`〇` 是模型 OOV**——我的规范化本来输出"二〇二六年"，模型会静默吞掉这个字念成"二二六年"。已改用 `零`。
2. **`/v6/speech/synthesize` 被全局 SQLite 锁串行化**——它根本不碰数据库，却会让每次 1.5s 的合成阻塞整个服务。已在中间件中豁免。
3. **`play()` 被自动播放策略拒绝时静默无声**——原来只是跳过，现在会抛出并回落到浏览器语音。已在浏览器中强制 `play()` 拒绝验证过回落链路。

另：项目目录名含中文（`F:\优活\...`），kaldifst 无法打开该路径下的 `.fst` 文件。因为客户端已完成日期/数字规范化，直接不启用 `rule_fsts` 即可绕开；模型建议放在纯 ASCII 路径。

功能审核在**语音启用与关闭两种配置下各跑一遍，均 105/105 通过**。

[CosyVoice 2](https://github.com/FunAudioLLM/CosyVoice) / [IndexTTS-2](https://arxiv.org/html/2502.05512v1) 音质更好但需要 GPU，更适合预渲染演示语音包。以上都不能替代 P0-1 要求的 HarmonyOS 官方 Core Speech 真机接入——但同一套文本规范化对 Core Speech 同样必需。

### 9.6 全方位排查（第二轮）

#### 无障碍：9 项真实 WCAG AA 不达标

本产品面向视力衰退的老人，设计稿也明确要求高对比度，因此对比度不达标是**产品缺陷**而非风格偏好。用真实浏览器读取计算样式（`color-mix()` 和 CSS 变量无法靠读样式表判断）逐元素测量，首轮发现 9 处低于 4.5:1：

| 元素 | 原对比度 |
|---|---|
| 模式徽标 `.badge` | 3.31 |
| 快捷按钮 `.quick button` | 3.49 |
| 状态标签 `.status-chip.todo` | 3.73 |
| 可信提示 `.trust-pill.neutral` | 3.78 |

扩展到全部 6 个页面 × 明暗两种模式后，又发现 `--ink-3`（4.33/4.11）、`.eyebrow`（3.34）、深色模式下 `.innovation-strip`（3.69）等问题。全部修复：着色文本改为"以 `--ink` 为主、只保留色相倾向"。

新增 `backend/scripts/check_contrast.py` 并接入 `verify_all`：**12 个页面/模式组合全部通过 WCAG AA**，同时校验触控尺寸与无障碍名称（识别包裹式 `<label>`）。检查器本身也修了两类误报：渐变背景与 `background-clip:text` 无法测量应跳过，半透明背景需与父层合成。

#### 复验脚本：三个会导致误判的缺陷

`verify_heavy` 从未被运行过，本轮首次执行即失败：

1. **负载脚本把传输错误当崩溃**（`run_load_v6.py`）。`asyncio.gather` 未设 `return_exceptions`，一个 `httpx.ReadError` 就让整轮 5000 次测量全部丢失并抛栈。根因是长连接竞态：uvicorn 5 秒回收空闲 keep-alive 连接，客户端恰好复用同一条。已改为**单次重试 + 计数上报**，现在 5000/5000 通过并如实记录 `keepalive_retries`。
2. **子进程输出写入永不读取的管道**（负载与烟雾脚本）。管道缓冲区写满会阻塞服务进程——可选 TTS 引擎正是从原生代码向 stderr 输出。已改为写入文件。
3. **烟雾测试 25 秒启动超时**在紧随 6 分钟负载测试之后不够用（此时机器仍有大量 TIME_WAIT 套接字）。已放宽至 90 秒，并对临时目录清理容错。
4. **长连接被服务端提前回收导致端口耗尽**。修好前三点后再跑，出现 5000 次中 **1912 次 `ConnectError`**。根因：本机 p50 延迟约 4 秒，请求在信号量前排队，而 uvicorn 默认 5 秒就回收空闲 keep-alive 连接——等排到时连接已被关闭，每次都得新建套接字，很快耗尽临时端口范围。把压测服务的 `--timeout-keep-alive` 提到 120 秒后，**重试次数从 1912 降到 0，5000/5000 通过**。脚本同时把 `ConnectError`（压测机套接字耗尽）与服务端错误分开上报，避免把环境限制误判成产品故障。

#### 老人日志被系统内部步骤刷屏

真实驱动一遍缴费流程后检查老人端日志：5 条里有 2 条是"生成了一张玻璃盒信任卡"。这个动作在每个确认回合自动触发，而卡片本来就已经显示在对话里，等于用系统内部步骤挤掉了"到底办了什么事"。已从老人可见白名单中移除信任卡与安全预演两项（**家属审计链仍完整保留**），并对相邻重复行做合并。新增回归测试固定这一行为。

#### 我自己引入的一个启动回归

`warm_up_async()` 先判断 `self.available`，而它会 `import sherpa_onnx`——一个重量级原生库——**同步发生在应用启动路径上**。已把探测移入后台线程并缓存结果。实测启动耗时：配置模型与不配置模型均为 **4.5s**（修复前配置模型会显著变慢）。

#### 性能：文档数字在本机无法复现

报告长期声称 **412 rps / P95 794ms**。本机实测：

| 并发 | 优活 | 裸 ASGI 对照 |
|---|---|---|
| 1 | 72 rps | 57 rps |
| 100 | 22.7 rps | 21.7 rps |

关键在于**对照组**：一个零业务逻辑的裸 ASGI 应用只快不到 5%，说明瓶颈是本机 Windows 回环栈而非应用代码。顺带把两个 `BaseHTTPMiddleware` 改写为纯 ASGI 中间件（行为不变、去掉 anyio 任务组开销），264 项测试全过。

**这条必须在答辩前处理**：不要在评委面前引用 412 rps，除非在比赛用机上重新测过。

### 9.7 核心创新升级：可验证复述确认 + 理解度闭环

#### 起因：第一号创新此前是空的

README 把"高风险使用复述确认"列为创新之首，设计稿 §4.2 明确写了话术"请您说'确认支付56.80元'"，`CognitiveLoadGovernor` 也会把 `confirmation_style` 设成 `TEACH_BACK`。但引擎里的判定是：

```python
def _is_yes(text):
    return any(k in text for k in ["确认办理", "确认", "可以", "好的", ...])
```

一个风险等级 4 的支付，老人说一句**"好的"就能过**。复述确认只存在于文档和字段名里。这是宣称与代码之间的真实缺口，评委只要照着演示脚本念一句"好的"就能戳破。

#### 现在的机制

新增 `backend/youhuo/teach_back.py`：付款前老人必须把金额说出来，系统解析口语中文金额并与**权威账单值**比对。

| 老人说 | 结果 |
|---|---|
| 好的 | `not_restated` — 不算确认，再问一次并告诉他该怎么说 |
| 确认支付六百八十块 | `mismatch` — 指出"您说的是680.00元，这次是68.40元"，停下 |
| 确认支付六十八块四 | `verified` — 进入家属接力 |

口语解析覆盖老人真实说法：`六十八块四`、`六十八元四角`、`六十八点四元`、`68块4`、`一百零五块`、`两百块`、`五块五分`。**误判会错误拦下老人，所以这里 28 项解析断言全部必须过。**

#### 闭环：观察到的理解度反过来调节交互

每次复述结果写入 `comprehension_events`（**只存结果标签，不存老人原话**），按 `0.7^n` 时间衰减加权成 0–1 的难度值，喂回 `CognitiveLoadGovernor`：

| 状态 | 风险2步骤是否要求复述 | 语速 | 负荷分 |
|---|---|---|---|
| 无历史 | 否 | 0.880 | 0.242 |
| 连续听错后 | **是** | 0.827 | 0.428 |
| 之后连续说对 | 回到否 | 恢复 | 下降 |

在此之前 `recent_retries` 由客户端传入且几乎恒为 0，治理器实际上只受风险等级驱动——"会自适应"这句话没有真实信号支撑。现在它有了。

**采用时间衰减是修 bug 修出来的**：平均窗口下，9 次说对之后 5 次旧错误仍把老人钉在"加强模式"，难度 0.367 卡在阈值上方。对老人来说这是错的行为，改成最近几次权重最高后双向自适应才成立。

#### 诚实边界

teach-back 是成熟的医患沟通方法，**不是我们提出的**。可主张的组合是：把它变成 Agent 副作用前的机器可验证门，比对权威工具值而非模型判断，失败作定点重解释，结果进审计链并驱动交互自适应。目前只对**金额**强制——让老人复述所有字段本身就是认知负荷灾难。

#### 验证

新增 `test_teach_back.py` 共 32 项（解析、判定、端到端、审计、隐私、不越界到挂号/提醒）。逐功能验收当轮新增 4 项、达到 109/109（当前总数见第 1 节）。同时更新了 14 个既有测试——它们此前都靠"确认办理"直接付款，正是被这个缺口掩盖的。

### 9.8 主要模式与次要模式升级（第三轮）

这一轮不是从代码往外找问题，而是**先当一次用户**：用 20 句真实老人可能说的话驱动一台真实服务器，看它回什么。结果是 20 句里有 15 句撞上同一句兜底文案。下面的每一项都由这次对话记录直接触发。

#### 一、无忧伴陪伴模式：连续三次倾诉，三次同一句话

实际记录：

```
「我想我老伴了」          → 我在听。您可以慢慢说，不着急。
「他走了三年了」          → 我在听。您可以慢慢说，不着急。
「我今天一个人在家很没意思」→ 我在听。您可以慢慢说，不着急。
「我想找个人说说话」      → （没有切换模式，回到办事菜单）
```

整个次要模式当时是四个硬编码分支。对一句丧偶倾诉重复同一行，比不回答更糟。

新增 `backend/youhuo/companion.py`：把一轮对话归入 8 个主题（丧偶/家人/孤独/睡眠/回忆/身体/日常/未分类），**丧偶排在家人之前**，否则"老伴走了"会被读成家庭趣事。同一主题第二次出现时改用承接句而不是开场句。会话级上下文**只保存主题标签和轮次计数，不保存老人的话**——这是设计稿 §6.2"必要短期上下文、不存对话本身"的结构化实现，因此它刻意留在内存里、不落库。重主题反复出现时给**一次**可以拒绝的联系建议，且只提示一次。

#### 二、"要不要接着聊"这句承诺此前是空的

任务锁会把闲聊暂存，办完后系统自己说"需要的话，我们可以切换到无忧伴继续聊"——然后老人回一句"好啊"，得到的是办事菜单。承诺和兑现之间没有代码。现在 `handle()` 在最前面消费这个待续话题：答应就切到陪伴并从那个话题开口，拒绝就说明怎么找回来，说别的就静默丢弃，不会隔了几轮突然翻旧账。

#### 三、跌倒：主链是所有安全层里最严的一层

`v5_services._EMERGENCY_TERMS` 和 `v6_services` 都把裸的"摔倒"当紧急，但 `security.py` 里主链的正则要求 `摔倒[^。！]{0,10}(起不来|不能动)`。也就是说，**唯一一个老人真的会对着说话的界面，判定最严**：

```
「我摔倒了」 → [chat] 我在听。您可以说"帮我挂号"…
```

放宽必须同时守住误报，否则家属会被"我上个月摔倒过"惊动。判定按**子句**做，而不是整句——中文时间状语在动词前，所以"去年摔倒住了院，现在好利索了"是康复叙述（含"现在"却不是现在），"刚才摔倒了，上个月也摔过"是正在发生。同时排除假设语气（"我怕摔倒""万一摔倒"）。21 项精确率/召回率断言全过。

#### 四、次要模式只有 REST 接口，嘴巴够不着

用药计划、服药依从、库存预测、健康时间线、亲友档案、适老交互档案在 v6 都已实现，但主链对它们一无所知：

| 老人说 | 升级前 | 升级后 |
|---|---|---|
| 我今天吃药了吗 | 兜底菜单 | 按权威计划与服药记录作答 |
| 我的降压药还剩几片 | 兜底菜单 | 库存预测，最紧急的排在最前 |
| 我血压怎么样 | 兜底菜单 | 念最近一条记录，不做判断 |
| 我今天有什么事 | 兜底菜单 | 未来 30 小时的真实待办 |
| 给我女儿打个电话 | 兜底菜单 | 念号码，并明说演示版不能替您拨号 |
| 你说慢点 / 我听不清 | 兜底菜单 | 老人自己改交互档案，服务端立即生效 |
| 今天几号 | 兜底菜单 | 日期、星期、时刻 |

新增 `backend/youhuo/care_voice.py`，三条边界写死在模块里：

1. **只在办事分类器空手而归时才被咨询**，所以"提醒我吃药"仍然是提醒任务，只有"我今天吃药了吗"才走这里。有测试固定这一点。
2. **除老人自己的交互档案外一律只读**。有副作用的动作仍走原来的任务链和确认门。测试断言查询前后服药依从数据逐字节相同。
3. **不做医学判断**。血压只复述记录值和测量时间。

两处诚实性设计值得单独说：

- **"降压药"无法解析时说出来，而不是猜。** 系统里没有药品分类表，把"降压药"映射到氨氯地平是一个没有来源的临床判断。实际回答是"我这边按药名记的，分不出哪种是您说的那类，把在吃的都说一下"，然后按剩余天数升序念——老人可能听完第一句就不听了，四天见底的那种不能排在三十天那种后面。老人直接说药名（"氨氯地平还剩几片"）时才收窄，且能匹配登记名的片段（记录写"苯磺酸氨氯地平"，老人只说"氨氯地平"）。
- **裸症状改为"提议"而不是"直接开单"。** 此前 `_classify_task` 把"膝盖疼"直接判成挂号任务。老人说"我头有点晕"并没有要求预约任何东西，替他决定是越权。现在回："我不能看病…要我帮您挂个号吗？…要是突然加重、说不清话、站不稳或者胸口发闷，别等我，直接打急救电话。"——点名危险信号不是诊断。带明确意图的"我膝盖疼，帮我挂号"仍然照常建任务。陪伴模式下的同一句话不走这条：聊天时提一句腰疼是倾诉，不是服务请求，交给无忧伴的身体主题回答。

顺带补齐办事分类器的真实说法：老人说科室和部位，不说"挂号"（"我要挂心内科""下周三下午去看牙"），也会说"要交的钱""欠费""物业费"。20 句探针从 5 句被正确处理提升到 18 句。

#### 五、前端跟着一起改

- 老人端新增"问问看"卡片，把四个照护提问做成可点的入口，并标注"这些只念记录，不做医学判断"；
- 语音改语速会写服务端档案，但页面上的下拉只有慢/舒适/正常三档。语音步进是 0.08，会落在档位之间——原实现会让下拉**变成空白**。现在越档值以"我调过的语速"显示，老人仍看得见、改得动；
- 收到改档案的回答后主动重新拉取权威档案，避免页面缓存与服务端不一致。

#### 验证

新增 `test_companion.py`（16 项）、`test_care_voice.py`（57 项）、`test_fall_detection.py`（25 项）。逐功能端到端验收新增 8 项。全部既有测试未作修改即通过——这一轮没有为了让新代码过关而改动任何旧断言。

### 9.9 多轮对话与界面实测（第四轮）

同样的方法，换一片没走过的地方：用 20 段**多轮**对话驱动真实引擎（改主意、方言确认、答非所问、说完又反悔），再把家属端全流程走一遍，最后用真实浏览器点开老人端。

#### 一、最严重的一条：任何听不懂的话都会改写任务内容

```
「提醒我明天上午九点复诊」 → 请确认：在2026-07-23 09:00提醒您"复诊"。
「嗯」                    → 请确认：在2026-07-23 09:00提醒您"嗯"。
「中」                    → 请确认：在2026-07-23 09:00提醒您"中"。
「谢谢」                  → 请确认：在2026-07-23 09:00提醒您"谢谢"。
```

等待确认时，凡是没被识别成"是/否/取消/闲聊"的话，都会被重新丢进槽位抽取，而 `_extract_reminder_title` 会把剩下的任何字当成新标题。日期和时间不受影响——**只有提醒的内容被悄悄换掉**，也就是这条提醒唯一有用的部分。老人说一句"嗯"，就会在正确的时间收到一条叫"嗯"的提醒。

两处修改：

1. **"嗯""中""行""成""对"整句匹配时算确认**。此前它们都不算，"中"在北方就是"行"的意思。整句匹配是必须的——"中"也在"中午"里，"对"也在"不对"里。
2. **结构性防线**：读回确认之后，只有能识别出**结构化槽位**改动（日期、时间、医院、医生、账单类型）的话才允许改任务；只动自由文本又没有"改成/不是/应该是"这类标记的，一律当作没听清，把任务原样复述一遍。

放宽确认词有个必须验证的副作用：**它不能放行付款**。付款仍由复述金额把门，"嗯"里没有金额，判定 `not_restated`，照样停下。有测试和逐功能验收各钉一条。

顺带修掉一个相关的：`「改成下午三点」` 会把标题改成"改成"。修法是在标题抽取里先去掉修正标记，并对"不是复诊，是取药"这类说法取分句后半段。

#### 二、改对了但不出声

`「不对，我要后天」`确实把日期改成了 7 月 24 日——然后回了一句和上一轮一模一样的话。老人无从判断改动是否生效。现在改动会被复述："好，日期改成2026-07-24。"

这个改动一上来就暴露了另一个更早的 bug：`「今天天气真好」`回了**"好，日期改成2026-07-22。"** 任何带"今天/明天"的句子都会被日期解析器抓出一个日期，闲聊因此一直在悄悄改预约时间，只是从前没人看见。现在的规则是：闲聊只有在改动了**日期解析器编不出来的东西**（医院、医生、账单类型）时才算作回答，纯日期/时间的改动一律丢弃。`「第一医院吧，我孙子说那儿好」`仍然算回答。

#### 三、三个死胡同

| 老人说 | 从前 | 现在 |
|---|---|---|
| 槽位没填完时说「确认办理」 | 原样重复上一个问题 | "这件事还差一项没定下来" |
| 「我不知道」 | 原样重复上一个问题 | "没关系，不着急……拿不准就先选第一个，之后也能改" |
| 「刚才那个提醒取消掉」 | **新建**一条提醒，开始问"哪一天提醒？" | 取消那条提醒并念出名字 |

第三条是真正的误路由："取消"里带着"提醒"两个字，办事分类器就把它读成了创建请求。想撤销的老人被塞了一个新任务。现在取消是保守的：只有唯一候选时才动手，否则把待办列出来问是哪一条——取消错提醒是老人要等到错过就诊才会发现的失败。另外加了**一轮撤销窗口**：刚听到"已经设置提醒：复诊"就说"算了，不要了"，取消的就是它；隔了一轮再说"算了"，不动任何东西。

#### 四、一句话说两件事，第二件被吞掉

`「帮我挂号，顺便把水费也交了」`只办挂号，水费一个字不提。刚性任务锁一次办一件是对的，但它得说出来。现在会答"另外缴费的事我记下了，这件办完再帮您办"，办完主动提起，答应就直接开单。判据是**连接词**（顺便/另外/还有）——没有它，"提醒我明天交水费"仍然是一件事而不是两件。

#### 五、界面上真正看到的两个问题

用浏览器点开老人端，第一条照护回答就露了两处：

1. **标注写着「闲聊」。** 照护回答的 code 是 `chat`（因为确实没有执行任何操作），前端把 `chat` 一律标成"闲聊"。一条按权威用药记录作答的话被标成闲聊，正好说反了。现在按意图标注："按用药记录回答""按库存记录回答""按健康记录回答"……
2. **中文标点被折成半角，句末句号丢失。** `clean_user_text` 的 NFKC 归一化把 `，` 变成 `,`——对**不可信输入**这是对的（同形字和控制字符防线），但 `CognitiveLoadGovernor._simplify` 把它用在了**我们自己要给老人看的句子**上。于是全应用每一条消息都是"用药计划,所以我这边查不到"。修法不是取消归一化，而是在**两个汉字之间**把折过的标点还原回全角——`08:00` 和 `126.50元` 的 ASCII 必须原样保留，否则 speech.js 的时间和金额正则会失配，读成"零八比零零"。句末句号是 `_sentences` 剥掉终止标点后 join 只在句间补回造成的，补上。

#### 家属端：没找到缺陷

审批、重复审批、事后审批已完成任务、拒绝、篡改审批摘要、跨家庭越权、家属替老人建会话、重复待办去重——全部行为正确。这一轮在家属端没有发现问题，如实记录。

#### 验证

新增 `test_conversation_robustness.py` 29 项，逐功能验收新增 5 项。修 `_extract_reminder_title` 时我自己写的测试先抓到了"改成"变标题的问题——这批用例是先失败再修好的，不是事后补写的。

### 9.10 发布卫生：交付检查放行了一个被推送到公开仓库的密钥（第五轮）

仓库上传到 GitHub 之后核对已提交内容，发现 `git ls-files` 里有：

```
backend/data/youhuo.db            598 KB，一份带演示数据的真实运行库
backend/data/youhuo.db.audit.key  32 字节，HMAC 审计链签名密钥
.coverage                         覆盖率二进制数据
```

而 `check_artifacts_v6.py` 在同一棵树上报告 `no_runtime_database: true`、`no_generated_audit_key: true`。

#### 为什么检查器会说谎

```python
runtime_db_files = ["data/youhuo.db", "data/youhuo.db-wal", "data/youhuo.db-shm"]
checks["no_runtime_database"] = not any((ROOT / name).exists() for name in runtime_db_files)
```

三条写死的路径。应用实际写到**启动目录**——`uvicorn --app-dir backend` 时是 `backend/data/`。检查器盯着一个位置，文件落在另一个位置，于是它诚实地报告了一件与事实相反的事。`.gitignore` 犯的是同一个错误：`data/*.db` 锚在目录上，`backend/data/` 一个都没挡住。`.dockerignore` 反而是对的（用的是 `*.db` 这种按名匹配），这也说明问题不是不知道该挡什么。

改成整棵树扫描，跳过 `.venv`/`.git`/`__pycache__`，并在结果里列出具体文件而不是只给一个布尔值。`.gitignore` 改成按名匹配。

#### 根因：`import youhuo.api` 会在磁盘上建库

真正的问题在更上游。`api.py` 结尾是：

```python
app = create_app()
```

`create_app()` 会 `mkdir` 数据目录、建库、灌演示数据、生成审计密钥。写在模块作用域，意味着**只要导入这个模块**——跑测试、生成 OpenAPI、编辑器加载、任何工具——就会在当前工作目录留下一套运行状态。文件就是这么进的仓库，而且删掉之后还会自己长回来。

改成 PEP 562 的模块级 `__getattr__` 惰性构建：`uvicorn youhuo.api:app` 不受影响（uvicorn 就是取这个属性，取的时候才构建），而 `from youhuo.api import create_app` 和 `import youhuo.api` 不再碰磁盘。改完之后跑完整 pytest，`data/` 目录只剩 `.gitkeep` 和演示药品 JSON。

#### 验证方式的修正

我最初写的断言是"发布树上不存在这些文件"，结果它在 `verify_all` 里失败了——因为当时 pytest 自己就在创建它们。这个失败是对的，但断言的位置不对：开发者本地跑过演示、有一份 `data/youhuo.db`，这不是缺陷；**同一个文件出现在 `git ls-files` 里才是**，那才是进了 GitHub 的东西。改成检查 git 跟踪状态，并另加一条断言：在临时目录里 `import youhuo.api`，之后目录必须还是空的。

顺带又踩了一次 CP936：`subprocess.run(..., text=True)` 读 `git ls-files` 时用本地编码解码，遇到仓库里的中文文件名直接 `UnicodeDecodeError`。已显式指定 `encoding="utf-8"`。

#### 诚实说明密钥的影响

这是本地生成的演示用 HMAC 密钥，不通向任何外部服务，泄露它不会造成账号或资金风险。真实代价有两条：一是本项目"审计链不可篡改"的说法，在密钥和数据库一起公开之后站不住；二是在竞赛仓库里出现这种文件本身就是减分项。密钥删除后下次运行会自动重新生成。

#### 验证

新增 `test_release_hygiene.py` 10 项：检查器能在任意深度发现泄漏产物、跳过 `.venv`、`.gitignore` 按名匹配、git 跟踪清单干净、导入模块不落盘。

### 9.11 公开免登录网页端（第六轮）

目标：给一个任何人打开网址就能用、不需要注册也不需要登录的地址。查下来有两个
真问题，都在"能部署"这条路上。

#### 一、Docker 镜像从来起不来

Dockerfile 只 `COPY backend` 和 `COPY xiaoyi`，然后 `RUN mkdir -p /app/data`。
`MedicationKnowledgeBase` 在 `create_app()` 里读 `data/medication_interactions_demo.json`，
而那个目录是空的：

```
FileNotFoundError: /app/data/medication_interactions_demo.json
```

容器启动即 crash-loop。docker-compose 还把一个命名卷挂在 `/app/data` 上，所以
**就算把文件拷进镜像也会被卷遮住**——只读参考数据和可变数据库放在同一个目录，
本身就是错的。

Docker 守护进程当时没运行，所以没有靠 `docker build` 证明，而是按 Dockerfile 声明的
COPY 集合在临时目录里搭出一模一样的文件树再启动应用，同样复现了这个报错，而且更快。
这个做法留成了 `test_deployment.py`：它**解析 Dockerfile 的 COPY 行**，所以将来
任何"应用需要但镜像没带"的文件都会让测试失败，而不是让部署失败。

修法：参考数据移到 `backend/youhuo/reference/`（随包发布，卷永远遮不住），缺失时
给出说清楚的错误而不是裸 `FileNotFoundError`；`CMD` 改成 shell 形式使用
`${PORT:-8000}`（Render/Railway/Fly/Cloud Run 都注入 `$PORT`，写死 8000 在每一家
都过不了健康检查），健康检查跟随同一个端口；容器用户改成 uid 1000（Hugging Face
Spaces 以该 id 运行，数据目录属于别人时应用建不了库）。

#### 二、公网上所有访客共用一个演示家庭

页面写死 `elder-demo`。在本机没问题，放到公网就是：两个评委同时打开，会看到对方
创建的提醒，也能改掉对方的任务。

新增 `POST /v2/auth/visitor`：每个浏览器首次访问自动播种一个独立家庭
（`fam-v<随机>`），ids 存在 localStorage 里，刷新沿用。家庭隔离本来就按 `family_id`
在各层强制执行，所以这是真沙箱：实测两个访客的待办互不可见，跨家庭读档案和写待办
都返回 403，审计链各自独立。新增 `identity.js` 统一解析身份，五个页面里 30 处写死的
demo id 全部改为动态；原来的固定 `elder-demo` 账户保留可用，本机演示和既有脚本不受影响。

写这一层时踩到的自己的坑：批量替换字面量时把刚写好的兜底默认值也换掉了，生成出
`let IDS = {elderId: IDS.elderId}` 这种自引用——加载即 TDZ 报错、白屏。`check_browser_js.py`

#### 三、又一次 CP936

### 9.12 手机 App 形态与前端升级（第七轮）

明确了最终形态是手机 App 之后，前端方向从"网页做漂亮"改成"**装到主屏就是一个 App**"。

#### 参考仓库：拉了 21 个，一个都没当依赖

按要求把两批顶级前端/移动端仓库拉到 `F:\优活\顶级前端仓库`（浅克隆，共约 1.5GB）。
必须说清楚：**它们全都不能作为本项目的依赖**，原因是平台和约束，不是取舍偏好——

- 原生端是**鸿蒙 ArkTS**（这是鸿蒙赛道），所以 RN Skia / Reanimated / Gesture Handler /
  HeroUI Native / RN Reusables / Rive RN / Lottie RN / Bottom Sheet / Victory Native /
  Filament 平台不对；Flutter Vignettes / Wonderous、SwiftUI Pow、compose-animations 同理；
- Web 端跑**严格 CSP**（`script-src 'self'`，无 CDN 无外部字体）且**没有构建链**，
  shadcn / Magic UI / Motion Primitives / Animate UI / COSS / Radix / Base UI 是
  React+Tailwind，引入等于整套重写。

但它们的**动效参数是可以直接搬的**，而且结论和"要炫"正好相反：

| 来源 | 实测参数 | 阻尼比 |
|---|---|---|
| gorhom/react-native-bottom-sheet | stiffness 1000, damping 500, mass 3, `overshootClamping: true`, ~250ms | ζ≈4.6，**重度过阻尼、明确关掉过冲** |
| ibelick/motion-primitives | `bounce: 0`, `duration: 0.2`, easeInOut | 无回弹 |
| Reanimated 的通用默认 | stiffness 100, damping 10 | ζ=0.5，明显回弹——而上面那个库刻意覆盖掉了它 |

两个独立的、口碑最好的实现都落在**无过冲、200–250ms、减速**。这也正是这个受众唯一
站得住的选择：回弹对前庭敏感的人读起来是"不稳"，而会过冲的控件就是会从手指底下跑掉的控件。
`--ease-out: cubic-bezier(.22,1,.36,1)` 就是"过阻尼且钳位"的贝塞尔近似——快出发、长收敛、绝不越过目标。
这些数值和出处都写进了 `style.css` 的注释里。

#### 做了什么

**装得上、像 App：** 新增 `manifest.webmanifest`（`display: standalone`、竖屏、快捷方式）、
`sw.js`、`register-sw.js`，以及 4 个尺寸的 PNG 图标。图标是 `make_app_icons.py`
用 zlib+struct **纯手写 PNG 编码器**生成的——包里没有 Pillow，也不该为几个图标新增依赖；
含 maskable 版本，否则安卓圆形裁切会把图形切掉。`/sw.js` 和 `/manifest.webmanifest`
从**站点根**提供并带 `Service-Worker-Allowed: /`，因为 worker 的作用域不能高于自身路径，
放在 `/static/` 下只能管住 `/static/`。

**Service worker 的边界是硬的：只缓存外壳，绝不缓存任何权威数据。** 账单、待办、用药、
审计链都是权威状态，把缓存里的"水费已缴"念给老人听，正是这个产品存在的意义所反对的。
`isApi()` 在 `respondWith` 之前直接放行，有测试钉住这条。

**手机外壳：** `viewport-fit=cover` + `env(safe-area-inset-*)`（缺前者时所有 inset 都是 0，
布局会压进刘海）、`100dvh`（`100vh` 在移动浏览器上高于可见区域，会把输入区顶出屏幕）、
`overscroll-behavior` 防整页橡皮筋、`-webkit-tap-highlight-color` 与 `touch-action`
去掉灰块和 300ms 延迟、`text-size-adjust` 防 iOS 横屏字号膨胀；≤760px 单列、
吸顶磨砂标题栏、主控件吸底到拇指可达区；`display-mode: standalone` 下补自己的顶部安全区
并隐藏返回链接（装成 App 后没有地址栏，返回到哪里对用户没有意义）。

**排版与设计系统：** 补上原本缺失的**间距标尺**（4px 基数）、**字阶**（最小 15px，
正文 17px 起，且全程不用细字重——细笔画是老花眼最先丢失的东西）、行高标尺

被文件后面的旧规则盖掉，成了死代码。

**语音：** 电话号码原先会被读成基数（`*******1111` → "一千一百一十一"），改为后端输出
"尾号1111"、前端把 `尾号` 后的数字逐位朗读；补 `mmHg`/`℃`/`kg`/`%` 等单位、
装饰性引号括号只从**朗读文本**里剥掉（屏幕上照旧显示）、省略号变停顿、
枚举顿号的停顿从 140ms 缩到 90ms（否则四个服药时间听起来像四句无关的话）。
