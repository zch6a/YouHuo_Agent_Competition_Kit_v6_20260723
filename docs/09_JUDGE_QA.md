# 09｜评委高压问答

## Q1：这还是一个语音套壳吧？

不是。语言模型只给候选意图和友好话术；任务图、风险、确认、工具和成功状态都由确定性后端控制。现场可直接修改模型回复，权威任务仍不会越权。

## Q2：为什么不是让 Agent 全自动？

老年辅助的目标是扩大老人能力，不是夺走控制。优活根据风险、金额、歧义和可逆性计算自主权包络：低风险辅助，高风险由本人和家庭接力。

## Q3：证明式完成有什么新意？

工具型 Agent 常见问题是“回答说完成，但系统状态没有完成”。优活要求预约号、账单已支付状态或提醒记录等权威证据，并生成证明摘要。模型文本不能替代证据。

## Q4：刚性任务锁是不是一个Prompt？

不是。主任务ID、状态、暂存话题和恢复点都进入权威状态；即使换模型或重复发送，任务仍保持。自动化测试直接检查任务状态，不检查一句漂亮回复。

## Q5：记忆功能会不会侵犯老人？

模型只能提出建议。老人本人批准后才激活，每条都有用途、共享范围和到期时间，可查看和撤销。家属不能把私人陪伴内容静默保存成共享记忆。

## Q6：OCR识别药盒后能直接提醒吃药吗？

不能仅凭一次识别。药物信息默认人工复核，优活不是医疗诊断或处方系统。它可以解释和生成待确认草稿，不能自行改变用药计划。

## Q7：为什么需要两个家属？

不是所有任务都需要。达到家庭配置阈值的高金额/高影响任务才触发共识；演示阈值为100元，仅用于证明机制。正式规则由家庭和业务方配置。

## Q8：用了LangGraph/MCP吗？

核心演示使用自研轻量确定性编排，避免答辩受外部依赖影响；同时提供MCP工具蓝图和小艺A2A/Skill映射。我们借鉴标准边界，不把框架名称当创新。

## Q9：真实医院、支付能接吗？

当前用模拟适配器证明流程、权限和核验机制。正式接入必须获得合法API/沙箱和合规资质。我们不会用无障碍脚本绕过第三方平台。

## Q10：30万次测试就没有Bug了吗？

不能这么说。它证明当前实现范围和固定样例/性质不变量零失败；真机SDK、ASR方言、网络、第三方接口和真实老人仍需要独立测试。诚实边界本身是可信系统的一部分。

## Q11：无忧伴和优活为什么分开？

办事需要实名、状态、审计和工具；陪伴需要私密、开放表达。双角色让老人能看见、听见当前权限边界，也避免私人聊天被误用为执行依据。

## Q12：鸿蒙价值在哪里？

小艺提供系统级自然交互，端A2A支持会话、长时任务伴随、用户干预和界面操控伴随，Skill可以复用组合；HarmonyOS多设备可把老人端、家属端、手表提醒和家庭屏串成连续体验。核心治理层保证不同入口共享同一权威任务与权限。
