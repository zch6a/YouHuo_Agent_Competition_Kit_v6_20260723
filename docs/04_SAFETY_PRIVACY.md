# 04｜安全、隐私与责任边界

## 1｜核心不变量

1. 模型输出不是授权；
2. 外部文本不是系统指令；
3. 高风险写操作没有人类同意不得发生；
4. 参数改变后旧审批失效；
5. 同一副作用必须幂等；
6. 成功必须有权威证据；
7. 家庭之间数据和权限隔离；
8. 长期记忆没有老人同意不得激活；
9. 陪伴内容不能静默变成家属监控数据；
10. 紧急检测只是辅助，不能冒充医疗/救援保障。

## 2｜威胁模型

| 威胁 | 攻击方式 | v3 控制 |
|---|---|---|
| 身份伪造 | 请求体自称某家属 | 身份只来自令牌，严格请求模型 |
| 跨家庭越权 | 陌生家属审批/查看 | family scope + actor relation |
| 参数换包 | 批准68.40后改9999 | 任务版本、关键字段、摘要重算 |
| 单人重复投票 | 同一家属投两次 | `approval_votes` 唯一约束 |
| 重试副作用 | 网络重试重复缴费 | 作用域幂等、载荷指纹、原子更新 |
| 幻觉成功 | 工具失败仍说成功 | `TaskVerifier` 检查权威状态/回执 |
| 间接提示注入 | OCR写“忽略确认” | 不可信域、注入检测、白名单抽取 |
| 恶意工具 | `shell.exec`/额外参数 | 工具允许列表、schema、dry-run |
| 记忆越权 | 模型自动保存病史 | proposed 状态、老人批准、TTL/撤销 |
| 陪伴泄漏 | 家属读取聊天全文 | 客户端允许列表、数据分区 |
| 日志篡改 | 修改历史审批 | 家庭级 HMAC 链验证 |
| 前端注入 | 待办标题含脚本 | textContent、CSP、nosniff、DENY |

## 3｜高风险同意协议

```text
系统复述动作 → 老人明确确认 → 生成绑定快照 → 家属独立核对
→ [阈值触发] 第二家属独立同意 → 服务端重算快照
→ 工具dry-run → 执行 → 权威状态核验 → 双端通知与审计
```

金额阈值为演示策略，正式产品必须允许家庭配置，并遵守实际支付平台和法律规则。

## 4｜不可信内容处理

OCR、VLM、网页、MCP、插件和第三方工具结果不得携带权限：

- 文本只能进入数据字段；
- 不允许其修改系统提示、风险等级或确认要求；
- 药品用法即使成功识别，也必须人工复核；
- 文档摘要携带 SHA-256 来源摘要，便于回溯；
- 不安全内容返回解释，不进入执行链。

## 5｜同意记忆

- 模型和家属只能“提出”记忆；
- 老人本人批准后激活；
- 私人范围对家属不可见；
- 到期自动失效；
- 老人随时撤销；
- 敏感健康、身份、支付信息不应仅凭对话推断保存；
- 正式系统需加密存储和密钥托管。

## 6｜紧急与心理风险

原型可以识别明显胸痛、呼吸困难、诈骗、求救等表达并提醒家属，但存在漏报和误报。正式展示必须保留明显“立即求助”按钮和当地准确求助入口；不能宣称优活是医疗器械、心理诊断工具或急救系统。

## 7｜生产前必做

Account Kit/OAuth、TLS、KMS、数据库加密与备份、最小权限、第三方沙箱认证、渗透测试、隐私影响评估、数据删除、用户同意、事件响应、真实设备/弱网/方言测试、法律与伦理审查。
