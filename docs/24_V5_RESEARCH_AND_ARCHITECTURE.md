# v5 研究借鉴与架构升级

## 1. 研究结论

优活 v5 不采用“让一个大模型自由读数据、规划并调用所有工具”的路线，而采用四层分离：

1. **语言层**：语音 N-best 共识、意图和澄清；
2. **控制层**：确定性任务图、Saga、版本和人工等待；
3. **治理层**：目的绑定、来源标签、最小权限、老人/家属确认；
4. **执行与证明层**：Schema 工具、权威状态观察、审计链和完成证明。

这一结构吸收了 LangGraph 的 durable execution / human-in-the-loop、Temporal 的长流程恢复思想、OPA 的 policy-as-code 分离，以及 CaMeL 将不可信数据与控制流隔离的安全原则。工程没有复制这些仓库源码，也没有为了比赛原型强行引入重量级依赖，而是实现可离线复现的最小可信内核。

## 2. v5 新增创新

### 2.1 N-best 语音共识
老年语音可能含方言、停顿、重复和相近词。系统同时接收主/备 ASR 候选，计算候选聚类一致性；支付、挂号等副作用任务采用更高阈值。确认/取消、金额或日期冲突时，必须追问而不是选择最高分候选。

### 2.2 目的绑定数据流
每个事实携带：来源、敏感级别、采集目的和是否可控制工具。OCR、网页、模型推断一律不能直接提供金额、收款人或授权。工具只接收当前目的所需字段，减少“拿陪聊信息去办事”或“文档诱导转账”的风险。

### 2.3 可恢复 Saga
挂号、缴费、复查、补药被建模为有版本的长流程：系统步骤、老人确认、家属批准、权威观察和最终核验。网络重试通过幂等键去重；中途失败后释放号源、作废支付请求或撤销提醒。

### 2.4 离线优先多设备同步
老人端和家属端可以在弱网下形成待同步操作。普通数据允许有限自动合并；健康、位置、支付状态等高敏感字段出现旧版本写入时创建冲突，必须由人选择，不能“最后写入覆盖”。

### 2.5 紧急破窗访问
在老人呼救、无法联系等明确紧急状态下，绑定家属可短时查看位置、健康摘要、紧急联系人和活动任务。权限自动过期并审计；陪聊原文、身份秘密和支付凭据永远不在破窗范围内。

### 2.6 可解释与可验证
老人和家属能查看：系统理解了什么、使用了哪些数据、为什么需要确认、当前能否撤销、最终成功依据。完成证明包含任务快照摘要、审计事件 Merkle 根和证明摘要；它用于检测包内证据被改动，不等同于区块链或第三方公证。

### 2.7 老人数据权利
老人可导出情绪事件、位置历史、实物记忆、联系人、医疗文档、健康事件和设备历史；删除采用预览—明确口令—执行两阶段流程。法律/安全必须保留的审计、审批和外部回执不会被伪装成可随意删除。

### 2.8 隐私安全可观测性
Trace 和指标在写入前递归脱敏；只报告澄清率、拒绝率、任务完成率和同步冲突率，不将陪聊原文、身份证、手机号或验证码送入遥测。

## 3. 与鸿蒙/小艺映射

- 小艺端 A2A 的 Context 对应家庭会话，Task 对应优活 Saga，Artifact 对应确认卡、进度卡和完成证明，Part 对应文本、卡片与状态更新。
- 长时任务伴随态用于挂号/缴费的暂停与恢复；输入不足时进入 INPUT_REQUIRED。
- HarmonyOS 工程壳预留 Core Speech、Account、Push、Location 和系统级 Agent/Skill 入口，但本包未冒充完成正式帐号申请、签名和真机审核。

## 4. 不采用的高风险做法

- 不让 LLM 直接持有支付、身份和远程控制权限；
- 不把提示词当作唯一防线；
- 不把 OCR/VLM 文本当作可信指令；
- 不因模型说“成功”就更新任务完成状态；
- 不以陪聊隐私换取家属监控便利；
- 不声称有限药物规则、体检解释或情绪分类是医疗诊断。
