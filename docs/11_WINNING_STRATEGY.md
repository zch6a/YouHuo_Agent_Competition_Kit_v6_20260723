# 11｜冲奖策略：从功能多转向证据强

## 1｜唯一主线

所有材料只讲一个问题：**让老人安全地完成数字生活任务，同时保留自主权。**

挂号、缴费、提醒、陪伴、记忆和拍照不是六个产品，而是同一可信闭环在不同场景的表现。

## 2｜创新证据

| 创新 | 现场证据 |
|---|---|
| 自主权包络 | 相同需求在不同金额/歧义下产生不同确认级别 |
| 刚性任务锁 | 插入孙子话题后任务ID和步骤不变，完成后恢复 |
| 证明式完成 | 工具说成功但数据库不一致时仍判失败 |
| 同意记忆 | 未批准不可用，家属不可见私人项，撤销立即生效 |
| 家庭共识 | 单个家属不足、同一人重复投票失败、第二人后完成 |
| 文档防火墙 | 恶意OCR文本被当数据阻断而非执行 |

## 3｜完备度

每条核心场景必须展示：需求→澄清→复述→确认→dry-run→工具→核验→通知/恢复。任何成功页面都能追溯到权威状态和日志。

## 4｜鸿蒙原生感

- 老人端大字、大触控、语音播报；
- 小艺端A2A长时任务状态和用户接管；
- Skill组合：任务安全、陪伴隐私、文档防火墙；
- 家属端Push/卡片接力；
- 后续真机展示手机＋手表/平板中的连续提醒。

## 5｜用户证据

宏观老龄化数据只能做背景。真正能拉开差距的是：

- 老人完成任务的点击/时间/错误下降；
- 能否正确复述金额、医生和角色；
- 是否感到被监控；
- 自主权偏好与家庭审批阈值；
- 真实访谈中“最怕点错哪一步”的原话（取得同意后匿名）。

## 6｜演示原则

- 先讲老人故事，再讲技术；
- 先成功流程，再展示攻击失败也安全；
- 不实时依赖公网和大模型，准备离线模拟和预录视频；
- 不把测试数量冒充用户数量；
- 不承诺真实支付/医疗生产接入；
- 评委问框架时回答机制与证据，而不是堆名词。

## 7｜决胜补强顺序

1. 真机HAP和小艺测试态Agent；
2. 12+老人/家属研究证据；
3. 5分钟演示达到逐秒稳定；
4. 一张架构图、一张自主权图、一张评测图；
5. 第三方沙箱/社区合作证明；
6. 全新电脑一键复现录像。
