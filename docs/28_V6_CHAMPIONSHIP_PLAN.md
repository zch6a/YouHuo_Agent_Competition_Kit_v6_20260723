# 优活 Agent v6 冲奖执行计划

## 1. 竞赛定位

优活参加的是“中国高校计算机大赛—人工智能创意赛”中的“鸿蒙高校创新赛·Agent创新方向”。官方强调自由创作、前沿创新、实用落地、鸿蒙全场景设备和多设备联动。项目不再用“功能最多”作为主叙事，而用一条完整故事证明：

> 老人能够用更低认知负担的语音完成数字事务；高风险时系统不猜测、不越权；家属只在必要节点接力；老人始终知道系统听到了什么、为什么需要确认、最终是谁做决定。

## 2. 决赛只讲三项核心创新

### 2.1 适老认知负荷治理器

- 一次只问一件事；
- 普通场景最多展示三项，高风险场景每轮最多一项；
- 根据语音置信度、重复次数、听力偏好调整句长、语速和字号；
- 高风险使用“复述确认（teach-back）”，而不是诱导式的“您确认吗”；
- 明确记录为何缩短、为何澄清、为何升级给家属。

### 2.2 玻璃盒信任校准

每个关键步骤生成一张可读卡片：

- 系统听到的原话；
- 当前目标和步骤；
- 使用了哪些数据、哪些已核验；
- OCR、网页或模型推断是否只是参考；
- 操作是否可撤销；
- 老人、家属和Agent分别拥有什么决定权；
- 下一步是什么。

目标不是公开模型内部思维，而是让老人形成“有证据的信任”，避免盲信。

### 2.3 安全动作预演与证据闭环

在挂号、缴费、健康资料等副作用动作前，系统先展示：

- 哪些字段允许使用；
- 哪些字段因来源、用途或敏感性被剥离；
- 需要老人还是家属确认；
- 失败如何回滚或补偿；
- 最终如何查询权威状态并生成完成证明。

v6新增了“可信工具值与OCR值冲突”的强制澄清：不能因为其中一个来源可信，就静默忽略另一个冲突值后继续执行。

## 3. 已完成的工程闭环

- 原有挂号、缴费、提醒、任务锁、情绪暂停、健康档案、用药、安全、位置和家庭协同；
- N-best语音候选共识；
- 目的绑定策略、Schema-first工具、Saga恢复、幂等与补偿；
- v6认知负荷治理、语义网关、玻璃盒依赖卡、安全预演；
- 真实HTTP演示页面 `/judge`；
- 用户实验登记与汇总接口；
- HarmonyOS API 26适配边界和决赛导览ArkTS页面；
- 小艺Skill、A2A Agent Card、工作流与89路径OpenAPI；
- ElderBench、VoiceBench、百万级性质测试和真实Uvicorn负载。

## 4. 仍必须由队伍线下完成的夺冠门槛

这些事项不能由离线代码包替代，也不能在答辩中虚构：

1. DevEco Studio编译、签名、HAP安装及至少两台鸿蒙设备实测；
2. Core Speech或正式语音能力接入，保存真机运行日志；
3. 小艺Agent/Skill/A2A平台创建、调试和审核截图；
4. 至少完成一个真实的手机—家属端协同链路；
5. 招募知情同意的老人和家属完成可用性实验；
6. 采集方言、噪声、停顿、重复、自我修正等真实语音；
7. 录制不依赖现场网络的稳定演示视频；
8. 把所有“模拟、适配器、未认证”边界放入作品说明和答辩备份页。

## 5. 三阶段推进

### 阶段A：稳定决赛主线

- 冻结主叙事和三项创新；
- 只允许修复P0缺陷，不再无限添加养老模块；
- 跑通 `/judge` 五步导览；
- 用正式设计稿统一蓝色优活、橙色无忧伴和信任卡视觉。

### 阶段B：真实鸿蒙与小艺证据

- ArkTS接入正式语音、推送和端A2A；
- 双设备演示“老人发起—家属确认—老人收到结果”；
- 记录弱网、断连、重复点击和恢复过程；
- 保存HAP、版本信息、平台截图、日志和演示视频。

### 阶段C：真实用户证据

- 先做2名老人探索性试用，修正术语和按钮；
- 再做不少于8名老人、4名家属的小规模形成性评估；
- 记录任务成功率、耗时、澄清次数、辅助次数、易用性和信任校准；
- 分开报告真实参与者、合成文本Benchmark和软件性质断言。

## 6. Go / No-Go门槛

提交决赛版本前必须同时满足：

- 核心自动化测试全部通过；
- 语音冲突、金额冲突、越权、重复执行和失败恢复均有现场可复现实例；
- 至少一条真实HarmonyOS双设备闭环；
- 用户实验有知情同意、匿名编号和原始记录；
- 演示视频全程无人工改数据库；
- 答辩PPT不出现“完全替代子女”“自动诊断”“自动支付”“绝对零错误”等不实表述。
