# 研究、标准与开源工程依据

## 1. 有状态 Agent 与 human-in-the-loop

LangGraph 等工程把长流程 Agent 建模为可持久化状态图，强调人工介入、恢复执行和记忆。优活没有直接复制其代码，而是使用轻量确定性状态机实现相同工程原则：模型理解语言，状态机控制权限、步骤和副作用。

## 2. 工具标准与最小权限

Model Context Protocol 强调工具 Schema、明确用户同意、安全元数据和对不可信工具描述的谨慎处理。优活的工具层采用严格输入输出模型、角色白名单、dry-run、高风险默认禁用和审批快照。MCP 适配只作为可选边界，不允许通用接口越过支付和身份控制。

## 3. 最终状态评测

τ-bench 的关键启发是：Agent 是否成功不能只看回复文字，而要检查最终环境状态。优活因此建立 Proof of Completion：订单、账单、提醒和关键字段必须与用户确认内容及工具状态一致。

AgentDojo 与 ToolEmu 展示了工具型 Agent 面临的提示注入、越权和危险副作用。优活据此加入不可信文档防火墙、跨家庭隔离、重复请求幂等、参数篡改检测和固定种子性质审计。

## 4. 老年人语音交互与照护设计

老年人 VUI 与 AI 社会支持研究反复强调：低操作负担、透明反馈、可撤销、个性化、隐私、自主权和人类社会支持不能被 AI 取代。优活据此采用：

- 一次只问一个选项；
- 当前角色和任务状态持续可见；
- 老人可暂停、拒绝和撤销；
- 家属只能在必要节点介入；
- 陪伴原文不进入家属报告；
- 情绪规则可解释且不做诊断；
- 低优先级通知聚合，避免家属疲劳。

## 5. HarmonyOS、小艺 Skill 与 A2A

项目按照小艺 Agent、Skill、工作流和 A2A 的能力拆分思路提供 Skill 文档、工作流节点、Agent Card 和 OpenAPI。Location Kit 的融合定位和地理围栏思想用于位置适配层；当前 Web Demo 使用本地演示 POI，真机仍需正式 SDK 与授权。

## 6. 健康数据互操作

健康事件导出参考 HL7 FHIR 的资源化结构，使用 Bundle、Patient 引用和事件资源表达。该输出用于展示可迁移的数据边界，不代表医疗机构认证或完整 FHIR 实现。

## 7. 药品标准化与相互作用边界

生产系统应使用权威药品标准化和相互作用服务。NLM RxNorm 可用于药品概念标准化，但旧 RxNav Drug Interaction API 已停止服务，因此本工程没有伪装在线接入；仅提供有限、可审计的演示规则，并对未知组合明确提示“没有发现不等于安全”。

## 8. 实现原则

- 借鉴架构和评测思想，不复制第三方仓库代码。
- 外部文本、模型输出和 OCR 均视为不可信。
- 高风险副作用由确定性策略控制。
- 所有“已完成”结论必须有可复验代码或报告。
