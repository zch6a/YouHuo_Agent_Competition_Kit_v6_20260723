# v5 安全保证论证（Assurance Case）

## 总论点
在比赛沙箱定义的挂号、缴费、提醒、健康归档和家庭协同范围内，优活不会允许模型单独越过老人意愿、家属审批、工具 Schema 和权威结果核验。

## 论点与证据

### G1 语音歧义不会直接触发副作用
- 机制：N-best 共识、高风险阈值、确认/取消冲突识别。
- 证据：`test_v5_services.py`、ElderBench-v5 voice 类、大规模 voice 性质测试。

### G2 不可信内容不能控制工具
- 机制：事实来源标签、目的绑定、控制字段剥离、禁止动作表。
- 证据：policy 单测、HTTP 注入烟雾测试、25 万项 purpose-policy 断言。

### G3 长流程可恢复且不会重复执行
- 机制：版本号、幂等键、角色门、Saga 补偿。
- 证据：400 个故障注入场景；200 条完成、200 条补偿，冲突推进均阻断。

### G4 高敏感跨设备冲突不会静默覆盖
- 机制：Lamport 时钟、实体版本、敏感级别、人工冲突解决。
- 证据：同步 API 测试、15 万项同步策略断言。

### G5 紧急权限受限且有时效
- 机制：白名单 scope、绑定家属、1–60 分钟过期、通知和审计。
- 证据：API 单测与真实 Uvicorn smoke。

### G6 完成声明可复核
- 机制：任务解释卡、权威回执、HMAC 审计链、Merkle 证明包。
- 证据：proof 单测、15 万项证明完整性断言、篡改负例。

### G7 陪伴隐私不被家属或遥测泄露
- 机制：禁止 disclose_companion_chat、最小化周报、递归脱敏 Trace、老人数据导出/删除。
- 证据：隐私测试和 10 万项脱敏断言。

## 残余风险

1. ASR、真实医院、支付、地图、推送和账号 SDK 尚未完成生产级接入；
2. SQLite 单机原型不等于分布式生产数据库；
3. 规则型情绪、药物和报告解释覆盖有限；
4. 真实老人、方言、噪声、弱网和无障碍用户实验仍不可替代；
5. Merkle/HMAC 只能检测本系统证据篡改，不提供外部可信时间戳或司法公证。
