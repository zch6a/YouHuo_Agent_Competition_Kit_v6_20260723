# 视觉评分卡

任务书要求 P0 页面 ≥94/100、其余 ≥90，并给出五个测试：5 秒测试、眯眼测试、
去掉边框阴影测试、AI slop 测试、App 测试。

**先说清楚这份文件该被信到什么程度。**

可测的部分（对比度、触控、溢出、无障碍、console、测试数）有仪器，数字在
[`TEST_REPORT_FRONTEND.md`](../../TEST_REPORT_FRONTEND.md)。

"好看"没有仪器。下面的分数是**我的判断**，不是测量。我不会把"我给自己打了 94 分"
当成通过标准来汇报——这个项目一贯的纪律是"仪器测的必须是你关心的那件事"，而这里
没有仪器。分数写出来是为了让它可以被反驳：每一条都指到具体元素和具体像素，你看
截图自己判断。

最后更新：2026-08-11。截图在 `frontend_redesign/screenshots/`（`shoot_pages.py`
生成，126 组 / 252 个文件）。

## 一、五个测试怎么做的

| 测试 | 做法 |
|---|---|
| 5 秒 | 打开截图看 5 秒，合上，写下"这是什么、我该做什么"。写不出来就是没过 |
| 眯眼 | 截图缩到 25% 再看：视觉层级还在吗，还是一团均匀的灰 |
| 去边框阴影 | 把 `border` 和 `box-shadow` 全去掉再看：结构靠留白和字号还站得住吗 |
| AI slop | 有没有：无理由的渐变、玻璃拟态、彩色 emoji 图标、"Bento 网格"、每个卡片都有的图标 |
| App | 这一屏像应用还是像网页？判据是：有没有嵌套卡片、有没有营销式 hero、主控件是不是唯一的重心 |

## 二、逐页

### `/elder` 老人端 · **P0**

| 项 | 判断 |
|---|---|
| 5 秒 | **过。** "这是一个能说话的东西，我按中间那个大圆" |
| 眯眼 | **过。** 缩到 25% 仍有三个层级：角色头、Voice Orb、底部输入行 |
| 去边框阴影 | **过。** 手机上对话面板和 `#chat` 本来就没有卡片外观（R6 去掉的三层嵌套圆角），气泡是唯一保留阴影的东西——因为它是这里唯一真的"物体" |
| AI slop | **过。** 无 emoji 图标、无玻璃拟态。唯一的渐变在 Voice Orb 上，它是主控件 |
| App | **过。** 定高框架、底部固定输入行、抽屉。没有 hero，没有嵌套卡片 |

**我的分：93。** 扣分点：

- 手机横屏（≤540px 高）下对话区只剩两行，构图是妥协出来的（`KNOWN_ISSUES` 第 1 条）
- 角色头在竖屏上占 100px，其中开场白那一行在她第二次打开时已经没有信息
- 「常说的话」三个 chip 的视觉重量和输入框接近，而它们的重要性不接近

### `/trust` 可信中心 · **P0**

| 项 | 判断 |
|---|---|
| 5 秒 | **过。** "这一页在证明一件事真的发生过" |
| 眯眼 | **过。** 凭证的时间轴竖线在 25% 下仍然是一条清晰的轴 |
| 去边框阴影 | **过。** 凭证靠时间戳列对齐 + 节点 + 竖线立结构，不靠卡片 |
| AI slop | **过。** 凭证刻意没有色块背景、没有圆角嵌套 |
| App | **勉强过。** 下面五个分区仍然是"标题 + 按钮 + 结果区"的演示卡形态 |

**我的分：91。** 扣分点：

- 凭证之下的五个分区还是老样子，和凭证不是同一套语言
- `.result` 里的 `<details>「原始响应」` 在每张卡上重复五次
- 「审计链自校验：完整」这颗药丸和上面四条底线的样式不成体系

### `/judge` 评委导览 · **P0**

| 项 | 判断 |
|---|---|
| 5 秒 | **过。** "七件事，跟着一次缴费" |
| 眯眼 | **过。** 序号 + 竖线 + 每拍最大那行字，三层清楚 |
| 去边框阴影 | **过。** 七拍本来就没有卡片，全靠竖线和留白 |
| AI slop | **过。** 删掉了五个图标 h2；序号是唯一的标记 |
| App | **过（对这一页而言）。** 它是一份可交互的说明，不是一个应用屏，所以按文档的标准看 |

**我的分：92。** 扣分点：

- 未演之前七个序号都是空心的、七句话是剧情提要——**这是有意的**（用七个实心蓝块
  假装它们已经发生过是这一页最不该做的事），但第一眼确实比演过之后弱
- `.beat-title` 那行小字和 `.beat-say` 的关系还不够明确，有时读起来像两个标题
- 页尾三个 CTA 按钮的排布是旧的

### `/family` 家人端

**我的分：90。** 四个列表的视觉密度接近，扫读时要靠标题分辨；审计流水在手机上仍然偏长。

### `/care` 照护中心

**我的分：90。** 六张卡的结构统一（好），但也因此扁平——没有哪一张在视觉上说"先看我"。

### `/` 首页

**我的分：92。** 两个入口、一句话，克制。扣分点：底部那行降级入口在深色下偏弱。

### `/stage` 演示舞台

**我的分：93。** 手机框中性、不模仿具体机型，桌面部分刻意什么都不做。扣分点：
左侧控制区四组按钮的分组标题字重偏轻，快速找不到「答辩模式」。

## 三、把这份文件读成什么

七页里六页在 90–93，没有一页到 94。**我没有达到任务书写的 P0 ≥94。**

这不是谦虚，是我看着截图给的判断：老人端的横屏构图、可信页上下两半不同语言、
评委页未演之前偏弱——这三条是真的，而且我知道怎么改，只是还没改。

需要有人反驳我的地方：如果你看截图觉得某一条不成立，那一条就该改分。这份文件的
价值在于它指得到具体位置，不在于那个数字。
