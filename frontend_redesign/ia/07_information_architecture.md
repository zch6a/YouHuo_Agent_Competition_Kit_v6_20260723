# 信息架构

七个页面，三种读者。这份文件写的是**每一页存在的理由**和**它默认给谁看什么**。

最后更新：2026-08-11。

---

## 一、三种读者

| 读者 | 她/他要什么 | 主场 |
|---|---|---|
| 老人本人 | 把一件事办掉，不想学任何东西 | `/elder` |
| 子女 | 知道爸妈今天怎么样，被叫到时能一键接力 | `/family`、`/care` |
| 评委 / 审计 | 这东西是不是真的，凭什么信 | `/judge`、`/trust`、`/stage` |

**一页只服务一种读者。** 这条规则解决了这个项目前一版最大的毛病：老人端曾经有
「演示挂号」这类脚手架按钮，可信页曾经把工程枚举名摆在正文里。混着服务两种读者，
结果是两边都不好用。

唯一的例外是首页 `/`：它的全部职责是把人分流到正确的那一页，然后消失。

## 二、七个页面

```
/            角色选择。两个入口：我是老人 / 我是家人。没有第三段内容。
├── /elder   办事与陪伴。手机专用，定高框架，输入行永远在屏上。
├── /family  今天怎么样 + 待办 + 审计 + 通知。
│   └── /care   照护中心：月报、体检解读、SOS、能力真值。
└── 给评委的三页
    ├── /judge  七拍故事。一位老人交一次水费，中间发生了七件事。
    ├── /trust  事务凭证 + 五个可信分区。
    └── /stage  桌面演示舞台。手机框里跑真实 App（真 iframe，不是缩放）。
```

### `/elder` — 一屏一件事

自上而下：角色头 → 今天有什么事 → 对话 → **Voice Orb** → 常说的话 → 输入行。

三条硬规则：

1. **输入行永远在首屏。** 打字是语音失败时唯一的退路，在 Firefox 上是唯一的入口。
   七个视口逐个量过。
2. **一次只问一件事。** 高风险时后端只回一个动作、并要求复述，而不是四个按钮。
3. **其余一切进抽屉。** 待办、常用、问问看、设置、我的记录都在 `#extrasSheet` 里。
   会话屏上只留会话。

Voice Orb 十一态是这一屏的主要状态载体：她不用读文字也能知道系统现在在干什么，
而读屏用户从 `#micHint` 和麦克风的 `aria-label` 拿到同一个信息。

### `/family` — 先说结论，再给细节

顶部三个数字（待您确认 / 进行中 / 今天到期），然后是需要她做决定的那几条，
最后才是审计流水。审计事件全部经过 `auditLabel()` / `actorName()` 翻译——
家属不该读到 `FAMILY_APPROVED_AND_EXECUTED`。

### `/trust` — 先给凭证，再给能力

**顺序是这一页这一轮最大的改动。** 原先是六张能力演示卡：每张能证明一件事，
但要评委自己把六件事拼成一次完整的办事经过。

现在：主张（一句）→ 四条底线（可点，跳到证明它的分区）→ **一次真实缴费的凭证** →
五个分区。凭证是"上面四条在一次真实缴费里长什么样"，分区是它每一环的单独证明。

### `/judge` — 七拍，跟着同一件事

她开口 → 听不清就不猜 → 一次只问一件 → 不听图片的金额 → 复述 → 家人点头 →
办好并说清楚。

每一拍两层：Product 层（默认可见，由**真实响应**填写）和 Proof 层（折叠：机制名、
接口、原始响应、单独重跑）。评分权重条和证据板搬到页尾——一位评委打开这一页，
第一眼不该是他自己的打分表。

### `/stage` — 桌面上的手机

真 iframe，不是 `transform: scale()`。App 必须在 390px 视口里**真的**跑起来：
媒体查询、`env(safe-area-inset-*)`、`100dvh`、抽屉的 `position: fixed` 全都依赖真实
视口宽度。缩放只是把桌面布局拍小。

## 三、导航

| 场景 | 出口 |
|---|---|
| 手机上的 family / care / trust / judge | 底部标签栏 |
| ≥761px | 标签栏隐藏，回到 `.back-link` |
| `/elder`（无标签栏） | `.back-link` **永远**显示 |
| 装到主屏（standalone） | 没有地址栏，所以标签栏或返回链接至少有一个必须在 |

最后一条曾经是死路：`standalone` 那段无条件隐藏 `body[data-nav="tabbar"] .back-link`，
理由是"只在另有出口时才隐藏"——它只考虑了老人端那个例外，没考虑宽度。装到主屏的
平板（竖屏逻辑宽 ≥761px）打开照护中心，四个链接全部不可见。

## 四、内容分层的一条通则

**产品层在前，证明层在后，工程标识只在最里面。**

| 层 | 例子 | 谁看 |
|---|---|---|
| 产品 | 「她把金额念了一遍」 | 所有人 |
| 证明 | 「系统等的是 68.40，听到的是 68.40，第 1 次通过」 | 想深究的人 |
| 工程 | `TEACH_BACK_VERIFIED` / `approval_digest: 37a6e…` | 折叠里 |

这条通则是可测的：`check_judge_story` 断言 Product 层不含英文，
`test_trust_receipt.py` 断言凭证正文不含事件枚举名，
`test_voice_orb_states.py` 断言十一态的标签里没有英文字母。
