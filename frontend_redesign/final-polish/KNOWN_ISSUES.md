# 已知问题

这份文件存在的理由：**不宣称绝对零 Bug**。这个项目声明的是"当前代码、测试、真实浏览器、
变异、人工视觉审计范围内没有已知 P0/P1"，而不是"没有 bug"。凡是知道、暂时不修或不能修的，
都写在这里，而不是让它安静地留在代码里。

## P2 · 照护页「身体」与「心情」两段在演示家庭里是空的

实测（打接口，不是猜）：

| 段 | 接口 | 演示家庭返回 |
|---|---|---|
| 身体 | `/v4/health/events/{id}` | `[]` |
| 心情 | `/v4/reports/emotion/{id}` | `event_count: 0` |

空态本身是**诚实的**，而且写得像产品（说清"以后会有什么、怎么才会有"，不是「暂无数据」）。
但一位评委打开这一页，五段里两段没有内容。

**为什么现在不修**：上一轮有一个 agent 在做这件事，它改了 `v4_store.py` 与
`baseline_store.py`，而**它自己写的测试正在报「情绪趋势是编造出来的上升」**——它死在
自己的变异测试上。那批改动已整段回退（用户裁决）。

**重做时必须避开的陷阱**（`api.py` 里写着，逐字读）：合成回填写的是 `activity_events_v4`
——一张运营表，无交互预警取其中的 `MAX(occurred_at)`。默认打开会让合成数据悄悄改掉
真实功能的输入。这比"演示里没东西看"糟糕得多。所以：显式开关、默认关闭、时间戳不许
落在未来、写之前 grep 那张表还有谁在读。

排期：Phase 7 之后单独做。

排期：Phase 7 打包时决定并执行，两种选择都要在 MANIFEST 里说清楚。

## P1 · 每一位打开演示链接的人，第一屏都是空的

老人端首页最重要的那一行，在**全新访客**那里写的是「今天没有要办的事。」

实测（不是猜）：`POST /v2/auth/visitor` 给每个浏览器开一个全新家庭，而
`Database.seed_demo()` 只种家庭、成员和三张账单，**一条提醒都没有**——
新访客的 `/v2/reminders` 返回 **0 条**。评委打开链接看到的就是这一屏。

这不是缺陷，是演示数据的缺口。但它的后果和缺陷一样：这个产品的主界面在第一次接触时
是空的。而 `api.py` 里给作息历史做回填的那段注释，讲的正是同一个道理——
「否则新开的家庭永远停在『还在熟悉他的生活规律』，个性化基线这个核心创新点在公网
演示里就是一片空白」。提醒同理。

**试过一次，回退了，理由要写下来**：我把三条提醒加进了 `Database.seed_demo()`，
一跑测试**红了 12 条**（不含指纹）——`seed_demo` 是**测试也在用**的那个种子函数，
往里塞待办会改掉一整批对话流程的语义：「取消」按名字找待办、裸「嗯」确认、
访客隔离计数。**层选错了。**

正确的层是 `api.py::visitor_sandbox()`，和作息回填同一个位置、同一个 `seed_history`
开关（只在演示部署里发生，真实部署不受影响），并且要同步更新
`test_visitor_isolation` 的计数期望。排到 Phase 7 之后和照护页数据一起做。

## P1 · 有了真实内容之后，「用打字说」掉出第一屏

上面那次尝试**顺带暴露了一个真缺陷**，而它一直被空态藏着：
一旦首页真的有待办（结论行 + 「下一件」卡片），
`test_the_typing_route_is_in_the_first_screen_on_every_viewport` **红了**。

也就是说：现在这套首页布局**是因为应用是空的才装得下**。
「用打字说」是语音失败时唯一的退路（A-01/A-04 两条 P0 都绕着它转），
它掉到折线以下，等于这条退路在有内容的真实使用中够不到。

这一条比上面那条严重，而且**必须连图一起改**（收紧「下一件」卡片、或让首页那一段
可滚而把 orb 与打字入口钉在视口内）。它同时解释了为什么演示数据不能当成"锦上添花"
的收尾项：**空态掩盖布局问题。**

排期：Phase 5，和数据一起——补数据和修布局是同一件事的两面，分开做会来回打架。

## P2 · `#status` 是老人端唯一的状态通道，而它默认不可见

`setStatus()` 写的是 `#status`，`#status` 在 `.elder-focus` 里，而
`pages.css:304` 是 `.elder-focus { display: none }` —— 只有进了 Focus Mode 才看得见。

12 个调用点里，**至少 5 处在 focus 关着的时候被调用**，那几句话一个字都不会出现在屏幕上：

| 调用点 | 那句话 | 什么时候发生 |
|---|---|---|
| `saveProfile()` ×2 | 「正在保存您的语音和显示习惯……」「已保存。」 | 在「我的」Tab 上调语速/字号 |
| `saveProfile().catch` | 保存失败的原因 | 同上，失败时 |
| `reminderAction()` 的 catch | 「这条待办没能更新：…」 | 在首页或「记录」Tab 上按待办按钮 |
| 启动链 `.catch` | 初始化失败的原因 | 页面刚打开就出错 |

本轮修掉的 A-04（`rec.onerror` 的六句话，含「让家人帮您在手机设置里打开麦克风权限」）
是同一个洞的**错误路径**那一半，而且是最要紧的一半——顺利的时候她不需要提示，
卡住的时候才需要。修法是在错误路径上 `setFocus(true)`：Focus Mode 恰好让
`#status`、输入框都显形，而麦克风不在被它藏起来的那一组里。

**剩下这 5 处不能照抄这个修法**：她在「我的」Tab 上点一下字号，被扔进对话界面是荒谬的。
这是一个**结构问题**（这一页只有一个状态通道，而它归 Focus Mode 管），不是五个 bug，
所以不在 Phase 3 里顺手改。排期：Phase 4/6，连同「状态行与 micHint 两条提示可能互相
矛盾」那条既有注释一起处理。

## P2 · 斜杠零关不掉，而两段注释描述了一个不存在的效果

`--numeric-plain: "zero" 0, "tnum" 1`。实测（把 woff2 内联进自足 SVG 后光栅化）：
`000` 默认墨量 **9301**，加上令牌之后**仍然是 9301**。字形中心像素检测显示 `0` 的
几何正中有墨、字母 `O` 没有——**这一版 Atkinson 的斜杠是 `zero` 字形本身的轮廓，
不是 OpenType `zero` 特性可以替换掉的字形**，所以那半个令牌关不掉任何东西。
对照组证明特性机制本身是通的（`"pnum" 1` 宽 132px vs `"tnum" 1` 宽 186px）。

`tnum` 那一半有效，保留。问题是 `tokens.css` 与 `pages.css` 两段注释**描述了一个
不存在的效果**，还点名了它要消灭的场景（家人端统计卡上的大号斜杠零）——而那个零
今天仍然在屏幕上。

修法（换一套数字字体）会改变全站每个数字与相邻汉字的字重字宽关系，属于**必须连图看**
的改动。排期：Phase 5，和重拍的对照图一起。

## P2 · CLS 闸门是单次采样，实测会抖

`check_layout_stability.py` 每个「路由 × 视口」只量一次载入期 CLS，然后拿单次结果
和 0.1 比。2026-08-14 实测到同一份代码在两次连续运行里给出不同判决：

    /family 390×844   一次 0.2613（红，源是 1370ms 的 nav.segmented）
                      另外三次 0.0000
    /care   1440×900  同一条位移的时间戳在两次运行里是 524ms 和 327ms

也就是说这道闸门此刻**同时会漏和会误报**：一次偶然偏低的采样能让真回归过关
（这一天 `/care` 那条 0.3687 的真回归就差点被当成抖动放过），一次偶然偏高的采样
又会让干净的代码报红、逼人去查一个不存在的缺陷。

不该靠调阈值解决——那只是选择要哪一种错。判据应该改成「N 次里的最坏值」
（N=3 起），并且把每次的采样值都打出来，让抖动本身可见。代价是这道闸门的时间
乘以 N（现在约 2 分钟）。

排期：和 Phase 7 的 Mutation Suite 一起收。**在那之前，这道闸门报的红要先重跑
一次确认，报的绿不能当成证据。**

## P2 · 家人端第一屏：H1 和它正下方那句是同一句话

`unknown` 状态下 `/family` 的第一屏是：

    H1     今天该有的记录还没出现
    紧接着 今天该有的记录还没出现（外出：今天还没有有效记录），建议打个电话问一声。

**先纠正这一条最初写下的诊断。** 我第一版写的是「后端 headline 把判定句原样当成
自己的开头从句」，据此把它排到「要动后端」。读完代码之后：不是那样。

`family.js:74-81` 有一段明确的取舍说明——短句进 `<h1>` 是**故意的**：

> 为什么不把 report.headline 直接放进 `<h1>`：那是完整的一段判断，最长的一条
> 「还在熟悉他的生活规律（已记录 0 天）。在攒够之前，不会拿别人的标准来评价他。」
> 38 个字，按 `.fam-head h1` 在 390px 屏上的 26px 排是**四行**——页头一个人吃掉
> 四分之一首屏，而「需要您确认」必须留在第一屏。

所以重复是那个取舍**已知的代价**，不是疏忽，也不是后端的问题。而且它不止
`unknown` 一个状态：

    typical  H1「他今天和平常差不多」    headline「今天和他平常差不多。」
    marked   H1「他今天和平常不太一样」  headline「今天和他平常不太一样：起床比平常晚了 96 分钟。」

每个状态下 H1 都在复述 headline 的开头，只是 `unknown` 那一条**逐字**相同，
所以看起来最像 bug；而演示数据正好停在这个状态。

Phase C 把 `/family` 顶部那条 `.segmented` 退役之后，这两行之间不再隔着一条导航，
**这个重复因此更显眼了**——不是新缺陷，是原本被挡住的一个。

正确的修法不是在前端截字符串（那是对一个结构化的句子做字符串手术，headline 的形状
一变就错），而是让后端把**结论**与**依据**分开给（例如在 `_headline()` 之外再出一个
`headline_detail`），前端 H1 用短句、下面一行只放依据。那是一次后端契约改动，
要连同 `/care` 与推送一起看——它们用的是同一份 headline。

排期：和 Phase D 的照护页文案一起收，那一轮本来就要动后端日报。
