## 一、动效

### 1.1 把状态交给动画去区分 【本项目】

`components.css` 的 Voice Orb 第一版里，`listening` 靠向外扩散的环、`speaking` 靠
呼吸、`clarifying` 靠"虚线不转"来和别的态区分。

`pages.css:692` 有一条全局规则：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation-duration: .01ms !important; animation-iteration-count: 1 !important; }
}
```

于是在开了「减少动态效果」的手机上，`listening` 和 `speaking` 都塌回 `idle`、
`clarifying` 塌回 `processing`。屏幕不再告诉老人 agent 正在说话——她按下去打断的是
agent 自己的回答。

前庭失调、偏头痛、晕动症的人开这个开关，而适老应用的用户正是最可能开它的一群。

**规则**：动效只能是第二层。每一态先要有一副**静止形态**（半径 / 线型 / 粗细 /
明度 / 饱和度），动效叠在上面。掐掉动效，所有状态仍两两可辨。

抓到它的闸门：`check_page_runtime.py :: check_voice_orb_states`——模拟
`prefers-reduced-motion: reduce`，再用 constructable stylesheet 把 transition 与
animation 全部停掉，逐态取计算样式指纹两两比对。

### 1.2 reduce 一刀切，把 opacity 也杀了 【外部】

motion 的源码把动画属性分成两类（`positionalKeys`），reduce 时**只杀位移 / 尺寸 /
缩放，保留 opacity 与颜色**。

rn-bottom-sheet 的源码里留着一行注释，说他们一刀切之后抽屉根本不出现了——因为入场
本身就是一次位移，杀掉位移等于杀掉"它出现了"这件事。

**规则**：reduce 要保留"发生了状态改变"这个信息，只去掉引发不适的运动。淡入是安全
的替代，瞬移不是。

> 这个项目目前用的就是 1.2 里说的那种一刀切（`pages.css:692`）。留着它是有意的：
> 全站没有依赖位移来传达信息的入场动画，而 Voice Orb 已按 1.1 改成静止形态可辨。
> 记在这里是因为**下一个加入场动画的人必须先读这条**。

### 1.3 用 cubic-bezier() 去近似过冲的弹簧 【外部】

判据只有一条：阻尼比 ζ ≥ 1（不过冲）才能写成 `cubic-bezier()`。ζ < 1 会越过终点再
回来，三次贝塞尔在数学上做不到。要过冲就用 `linear()`（纯 CSS，无需库）。

iOS 抽屉那条 ζ=4.56 的弹簧数学上要 2280ms 才收敛，但 349ms 就走完 50% 的位移。
诚实的翻译是 `350ms cubic-bezier(0.22, 1, 0.36, 1)`，不是 2280ms。

## 二、CSS 架构

### 2.1 在共享样式表里用通用名词当类名 【本项目】

新建桌面演示舞台时给容器取了 `.stage`。老人端本来就有
`<section class="panel stage">`（对话面板）。于是舞台的 `min-height: 100svh` 落到了
老人端那张定高面板上，把框架撑出 90px，内容被裁。

抓到它的：`test_no_page_clips_its_own_content_at_390x844`。
改名 `.demo-stage` 之后消失。

**规则**：四层样式表是全站共享的。`.stage` / `.card` / `.panel` / `.item` 这类词在
一个已经有六个页面的项目里必然撞车。新组件的类名带上它所属的那一块（`.demo-stage`、
`.device-caption`）。

### 2.2 用内联样式去"设置"一个 CSS 要钳的值 【本项目】

`stage.js` 原本写 `device.style.setProperty('--screen-h', h + 'px')`，而 `pages.css`
里那条响应式 `min(var(--want-h), calc(100svh - var(--chrome)))` 想给它封顶。
内联样式永远赢，封顶从来没生效过。

**规则**：JS 只提**需求**（`--want-w` / `--want-h`），上限由 CSS 钳。这条边界一划开，
"窄屏时不许超过视口"就变成 CSS 自己能保证的事，JS 不需要知道视口有多宽。

### 2.3 把媒体查询块写在它要覆盖的组件之前 【本项目】

媒体查询**不增加特异性**。`@media (max-width: 760px) { .elder-layout { ... } }` 写在
`.elder-layout` 声明之前，就会被后面那条同特异性的规则全胜。

`pages.css` 因此把全部响应式覆盖集中放在文件**最末尾**，并在那里写了理由。

## 三、无障碍

### 3.1 用 opacity / visibility 去"隐藏"一整块控制区 【本项目】

演示舞台的「答辩模式」第一版只是把控制区降透明度。控制区仍在可访问树里、仍可 Tab
到、仍可点。录屏时一次误触就把「场景：诈骗」这种按钮请回画面。

**规则**：要真的移除就用 `inert` + `aria-hidden="true"`，并且**必须留一个出口**
（这里是右下角一个半透明按钮 + Esc），否则键盘用户进得去出不来。

### 3.2 整块 `inert` 而没有恢复路径 【本项目】

老人端在 ≥761px 时侧栏整个 `inert`，而没有任何一个控件能把它解除。八路审计里这条
是 P0：键盘用户在宽屏上永远够不到那一栏。

### 3.3 `min-height` 对行内元素无效 【本项目】

这个项目踩过**三次**同一个坑：首页演示入口、家人端正文里的可信中心链接、舞台的
退出链接。`<a>` 默认 `display: inline`，`min-height: 48px` 对它没有任何作用。
对比度闸门量出退出链接的命中区是 156×16。

**规则**：触控目标必须是 `inline-flex` 或 `block`。

### 3.4 只靠颜色区分状态 【本项目】

见 1.1。补一条独立的：模式切换（优活 / 无忧伴）除了配色，还必须有**名字、图标、
开场白、音高**四样跟着变——这是 Design §4.1 表一的要求，理由是色觉障碍用户拿不到
配色这个通道。

## 四、仪器

这一节最重要。这个项目在闸门上花的时间比在特性上多，而**闸门自己出过的错比特性还多**。

### 4.1 依赖缺失被当成"跳过"，然后打印 PASS 【本项目】

`websocket-client` 不在 `requirements.lock.txt` 里，CI 只装 lock 文件。三个浏览器闸门
全部走到 `except ImportError: return 0`，验证链紧接着打印
`ALL V6 DETERMINISTIC VERIFICATION STAGES PASSED`。

**CI 从来没有在真实浏览器里加载过任何一个页面。** 把 `care.js` 第一行改回那个让两
整页按钮全死的 TDZ 缺陷，CI 照样全绿。

**规则**：缺依赖是**硬失败**。"这台机器没装调试工具所以我们跳过运行时验证"和
"运行时验证通过了"在汇总行里长得一模一样。

### 4.2 检查跑了，但什么都没量到 【本项目】

`check_voice_orb_states` 第一版在找不到 `.mic-dial` 时静默 `return`。它在六个没有
Voice Orb 的页面上正确地什么都不做——也会在 `/elder` 改名之后同样什么都不做，而汇总
行照样绿。

**规则**：把量到的**数量**印进汇总行，并对数量本身设下限。这个项目的汇总行现在是
「7 个页面 / 84 个控件 / Voice Orb 11 态 / 对比度 14 项」，每个数字掉下来都会红。

### 4.3 一个会给你看昨天的构建的截图工具 【本项目】

复用 Chrome profile 时，service worker 会从缓存里给出上一次构建的外壳。收起设置分区
之后量到的高度"没变"——因为量的是昨天那一版。

`shoot_pages.py` 自己的注释里写着这句话："一个会给你看昨天构建的截图工具不是测量，
是传闻。" 每次跑前 `shutil.rmtree(profile)`。

### 4.4 变异测试自己也会说谎 【本项目】

两次"绿"其实是**我没有制造出缺陷**：一次是重排 HTML 属性顺序，一次是调换 class 里
词的顺序。两者都是等价改写，一个写对了的正则本来就该保持绿。

**规则**：变异变绿有两种解释——闸门不守，或者你没造出缺陷。必须先排除后者再下结论。
反过来，一次变异脚本里混进了一行 JS 注释（`//`）导致 SyntaxError，四个变异**全部**
报红——那是四次假红。

### 4.5 `(retrieval or {}).get(..., False)` 【外部经验，同类】

默认值 `False` 把"从来没测过"变成了"测过并且失败"。这个项目里对应的一条是
`if "back-link" not in html: continue`——把"这一页没有出口"当成了"这条断言不适用"。

**规则**：缺数据的默认值必须是"未知"，不能是任何一个业务取值。

### 4.6 汇总行里的数字自己少报一半 【本项目】

`shoot_pages.py` 报「108 张」而实际写了 216 个文件——它数的是组数（首屏/全页算一组）。
一个自己少报一半的仪器，你没法用它的输出去比较两次运行。

## 五、内容

### 5.1 把引擎的枚举值给用户看 【本项目】

Web Speech 的 `e.error` 是 `not-allowed` / `audio-capture` 这样的英文标识符。直接显示
已经够糟，配一句"请再说一遍"更糟——权限被拒时再说一百遍也不会成功，而页面从不告诉
她要去哪里打开。

这一页为此写了四张翻译表。`RECOGNITION_TROUBLE` 里 `not-allowed` 对应的是
"我没有拿到麦克风的许可。您可以在下面打字，或者让家人帮您在手机设置里打开麦克风权限。"
——它给出**这一种失败下真正可行的两条路**。

`test_voice_orb_states.py :: test_state_words_are_things_an_elder_would_say` 现在直接
禁止状态标签里出现任何英文字母。

### 5.2 用 emoji 当系统图标 【外部 + 任务书】

emoji 由字体渲染，跨平台形状完全不同，读屏会念出它的 Unicode 名称，而且它没有
`currentColor`——深色模式下不会跟着变。emoji 只出现在真实的用户内容里。

### 5.3 藏起来，而不是改掉 【本项目】

老人端那三个快捷按钮曾经在手机上 `display: none`，注释写着"演示快捷方式是给评委的，
不是给王奶奶的"。那个判断在当时是对的——按钮上写的是「演示挂号」「演示缴费」。

但正确的做法是改掉标签而不是藏起来。现在按钮上的字就是它替你说出口的那句话
（「今天有什么事」「交水费」「挂号」）。对一位不知道该怎么开口的老人，这三个词恰恰
是这一屏最有用的东西——"不知道说什么"正是语音产品最常见的卡点。

**规则**：一个元素"在这个语境下不合适"，先问它换个说法是不是就合适了。

## 六、这份文件自己的边界

这里每一条都对应一个真实后果，但它们**不是**一份完备清单——它是这个项目到目前为止
撞过的墙。没有撞过的墙不在上面。

尤其没有覆盖的：性能（这个项目没有构建步骤、没有 CDN、没有网络字体，所以没遇到过
包体积和字体闪烁那一类问题）、国际化、以及任何服务端渲染相关的坑。
