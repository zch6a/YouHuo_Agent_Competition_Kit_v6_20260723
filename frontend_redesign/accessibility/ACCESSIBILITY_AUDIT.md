# 无障碍审计

七个页面。这份文件分两半：**测出来的**（有仪器、有数字）和**判断出来的**（我的
判断，可以反驳）。两半分开写，是因为把它们混在一起会让判断借到测量的可信度。

最后更新：2026-08-11。

---

## 一、测出来的

### 1.1 对比度与触控尺寸

`backend/scripts/check_contrast.py`，14 个组合（7 页 × 明暗），全部通过。

判据：

- 正文 ≥ 4.5:1（WCAG AA）
- 大字（≥18.66px 且 ≥700，或 ≥24px）≥ 3:1
- 非文本（边框、图标、状态点）≥ 3:1（WCAG 1.4.11）
- 触控目标 ≥ 48×48 —— **这是项目自己的下限，比 Apple 的 44 高**，理由是目标用户
  手抖

这条检查曾经只在 1360px 下跑，而且用 `!el.offsetParent` 跳过了 261 个文本元素里的
122 个。现在两个宽度都跑，可见性用命中测试判定。

### 1.2 运行时无障碍五项

`backend/scripts/check_page_runtime.py`，7 个页面，每页检查：

| 项 | 判据 |
|---|---|
| 标题层级 | 每页恰好一个 `<h1>`，`<h2>` 不跳级 |
| 图片替代文本 | 每个 `<img>` 有 `alt`，装饰性的是 `alt=""` |
| 表单标签 | 每个 `<input>` 有 `<label>` 或 `aria-label` |
| 按钮可读名 | 每个 `<button>` 有文本或 `aria-label`（纯图标按钮必须有后者） |
| 焦点可见 | 每个可聚焦元素在 `:focus-visible` 下有可见的环 |

同一次运行还会**逐个按下** 99 个控件，并检查 console 无 error、无未捕获异常、
无同源 4xx。这一条比五项静态检查更重要：一个 TDZ 崩溃会让整页按钮全死，而五项静态
检查全绿。

### 1.3 键盘可达

- 全站没有 `tabindex > 0`。
- 抽屉打开时焦点进入抽屉，Esc 关闭并把焦点还回触发它的按钮。
- 演示舞台的「答辩模式」用 `inert` + `aria-hidden` 真正移除控制区，**并留了一个
  出口**（右下角按钮 + Esc）。这一条是补的：老人端在 ≥761px 时曾经整栏 `inert`
  而没有任何恢复路径，键盘用户在宽屏上永远够不到那一栏。

### 1.4 减少动态效果

`prefers-reduced-motion: reduce` 下全站动画掐到 .01ms、迭代一次。

**这不够，所以另有一条闸门。** Voice Orb 的十一个状态如果只靠动效区分，开了这个
开关的手机上就会有三态塌回别的态。`check_voice_orb_states` 模拟 reduce、停掉全部
过渡与动画，再逐态取两道环与 orb 的计算样式指纹两两比对——十一态两两不同。

### 1.5 屏幕阅读器可达的状态

Voice Orb 的每一态有两处文字出口：

- `#micHint`（`role="status" aria-live="polite"`）——环下面那行字
- 麦克风按钮的 `aria-label`——读屏用户看不到环，环的全部信息从这里出

十一态的标签在 `elder.js` 的 `ACTIVITY` 常量里一处定义，
`test_voice_orb_states.py` 钉住：每态都有、两两不同、里面不许出现英文。

### 1.6 首屏可达

`test_the_typing_route_is_in_the_first_screen_on_every_viewport`：七个视口下
`#text` 必须**整个**在首屏里，而且中心点命中测试点得到。

这条不是排版洁癖。打字是语音失败时唯一的退路，在 Firefox 上（没有 Web Speech）是
唯一的入口——够不到就等于这个功能不存在。改之前 1024×768 差 156px、1280×800 差
138px、844×390 差 522px。

### 1.7 语言与朗读

- 每页 `<html lang="zh-CN">`。
- 朗读层（`speech.js`）把日期和金额转成口语：`68.40` 念「六十八块四」而不是
  「六十八点四零」，`2026-07-28` 念「七月二十八号」。34 项断言。

## 二、判断出来的（这是我的判断，不是测量）

下面这些没有仪器。我给出判断和理由，你可以反驳。

### 2.1 做到了的

**颜色从来不是唯一通道。** 两个模式（优活/无忧伴）除了配色，名字、图标、开场白、
音高四样都跟着变。Voice Orb 十一态在灰度联系表上两两可辨——这一条我拍了图看过，
而且第一版**没通过**：processing / executing / clarifying 三个虚线环肉眼几乎一样，
pressed 的环被 orb 整个挡住。

**错误信息给的是出路，不是描述。** Web Speech 的 `not-allowed` 不显示成
"权限被拒"，显示成「我没有拿到麦克风的许可。您可以在下面打字，或者让家人帮您在手机
设置里打开麦克风权限。」——它给出这一种失败下真正可行的两条路。

**没有 emoji 当图标。** 全站图标是内联 SVG，`currentColor`，深色自动跟随。

### 2.2 没做到的

**没有一位真实老人用过这个东西。** 所有适老化判断来自设计规范、参考实现和推理。
这是最大的缺口，比下面几条加起来都大。

**没有在真实读屏软件上跑过。** 语义标记、`aria-live`、标签都按规范写了，但
NVDA / VoiceOver / 鸿蒙读屏都没有实测。"标签存在"和"读起来是通顺的"是两件事。

**没有测过 200% 缩放。** 浏览器缩放到 200% 是 WCAG 1.4.4 的要求。全站用 `rem` 和
`clamp()`，理论上跟得上，但没有量过。

**没有测过高对比度模式（Windows 强制颜色）。** `forced-colors` 媒体查询一条都没写。

**动效的 `linear()` 弹簧只在 Chromium 上验证过。**
