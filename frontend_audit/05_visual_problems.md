# 视觉与信息架构问题（实测，非印象）

判据不是"我觉得不好看"，是可以指到具体像素和行号的事实。

## A. 首页是项目目录，不是产品

390px 下整页 **8574px**。

- Hero 第一行：`C4-AI · HARMONYOS AGENT INNOVATION · V6.0`——用户看到的第一句话是赛事元数据。
- 六张导航卡里排第一、`.card.featured` 视觉权重最高的是**「五分钟决赛导览」**，即比赛演示是这个产品首页的主 CTA。
- 一条九项的工程术语横滚带：认知负荷治理 / 玻璃盒依赖校准 / 自主权包络 / 语音共识 / 目的绑定策略 / 可恢复Saga / 证明式完成 / 家庭共识 / 同意记忆。
- 底部一整块 `ENGINEERING EVIDENCE 可复核工程证据`。
- 底部导航第五格是**「评委」**。

一个真实用户（老人或其子女）在这一页上没有任何可以完成的任务。

## B. 家属端是 Admin Dashboard

390px 下整页 **11121px**，约 13 屏。**12 张同等视觉权重的白卡**：

1. 今日生活日报（内含三个子块，各带 pill）
2. 需要您做的（绿色 notice）
3. 待您确认 `0`
4. 进行中 `0`
5. 今天到期 `0`
6. 审计链 `完好`
7. 待办日历 → **暂无待办**

四张卡的内容是"暂无"，却占据与真实内容相同的卡片权重。

**工程标识直接暴露给家属**（第 12 张卡）：

第 11 张卡里有两行是"是否包含聊天原文 否""是否给出医学诊断 否"——那是写给评委看的工程保证，不是家属要读的信息。

家属打开这一页想知道"我爸今天怎么样"，答案在第 1 张卡里，但它和另外 11 张长得一样重。

## C. 老人端首屏有演示脚手架

`elder.html:66-68`，三个按钮的**字面标签**：

```html
<button data-text="帮我挂明天下午两点第一医院骨科王医生的号">演示挂号</button>
<button data-text="帮我交水费">演示缴费</button>
<button data-text="提醒我明天上午九点复诊">演示提醒</button>
```

同一个文件第 133-145 行反而是对的写法——「我今天吃药了吗」「我的药还够吃吗」「我今天有什么事」「我血压怎么样」，是老人真会说的话。两种做法在同一页并存，说明前者是没清理干净的演示脚手架。

老人端首屏的**构图本身是好的**：问候 → 一条气泡 → 大麦克风（116vp，全页最大控件）→ 输入行 → 抽屉入口，一屏放得下。所以老人端是改内容不改骨架。

## D. 设计系统没有在起作用

不是"令牌不够好"，是**声明了却没有人用**：

| 维度 | 事实 |
|---|---|
| 字号 | 91 处 `font-size` 声明，只有 **5 处（5.5%）**引用令牌。21 个字面像素值覆盖了 11–22 的每一个整数——那是连续谱，不是音阶。另有 9 条各写各的 `clamp()` |
| 间距 | 221 个 `margin`/`padding`/`gap` 像素字面量中 **137 个（62%）不是 4 的倍数**，而 `tokens.css:101-103` 的注释声称"以下全是 4 的倍数"。最高频的三个越界值：14px（23 次）、10px（20 次）、18px（16 次） |
| 阴影 | 33 处声明中 **14 处是一次性手写阴影**，且**全部没有深色模式取值**。其中 6 处是手搓的焦点环，而 `--ring` 令牌已经存在 |
| 圆角 | 54 处中 11 处是脱离 10/14/18/20/26 阶梯的任意值（15/17/22/6/3px），另有 2 处把 `--r-xl`(20) 和 `--r-2xl`(26) 的值原样抄成字面量 |
| 令牌利用率 | 73 个令牌中 **9 个从未被引用**。`--text-sm` 无人用，而它的精确值 `15px` 被手写了 17 次 |
| 未令牌化的颜色 | `tokens.css` 之外有 **51 个颜色字面量**，其中 21 个是真正的调色值且**没有深色覆盖** |

## E. 由此产生的四个真实缺陷（不是审美问题）

| 缺陷 | 位置 | 后果 |
|---|---|---|
| `.shell` 的安全区内边距**从未生效** | `base.css:85-86` 设 `padding-left/right: max(--space-4, env(safe-area-inset-*))`，`base.css:111` 又用 `padding` 简写覆盖四边 | 刘海屏横屏时内容会压到挖孔下面。声明存在、注释解释了它、但它一次都没有生效过 |
| 深色模式下危险按钮仍是亮红 | `components.css:216` 写死 `#d8434e → #a81f2a`，绕开 `--danger`（深色应为 `#ff8c93`） | 全站唯一一个不跟随深色模式的语义色，而它恰好是"删除/拒绝"这类不可逆操作的按钮 |
| 5 条声明永远不可达 | `@media (max-width:720px)` 里的 `.mic-dial`/`.mic-big`/`.mic-big svg`/`.hero-head`/`.chat`，被其后的 `@media (max-width:760px)` 全部覆盖 | 有人写了它们、以为在调小屏尺寸，实际一次都没有应用过 |
| `--role-ink` 没有 `:root` 兜底 | 只在 `components.css:445/452` 的 `body[data-mode=...]` 里定义，被 `.head-icon` 和 `.tab.is-current` 消费 | 任何一页漏写或写错 `data-mode`，这两处颜色就退化成 `inherit` |

另外：`tokens.css:7` 的注释引用 `backend/tests/test_stylesheet_layers.py` 作为层序的守卫——**那个文件不存在**。真正的守卫是 `test_pwa_shell.py::test_stylesheet_layers_load_in_cascade_order`。这条注释是上一轮我自己写错的。

## F. 分层名存实亡

四个文件是按**原文件行号**机械切开的，不是按含义：

- `base.css` 24 个规则块里 **12 个**含组件类名（`.bubble` / `.rail-note` / `.entry-btn` / `.mic-big` / `.eyebrow` / `.lead` / `.meta` …共 25 个）
- `components.css` 里有 **21 条自定义属性声明**（属于 tokens）、**14 个元素重置块**（属于 base，包括 48px 触控下限和全站唯一的 `:focus-visible`）、以及 **63 个只出现在单页的类**（46 个是老人端专有）
- `pages.css` 里有全局 `*` 的减少动效重置（属于 base），以及**两个完整组件**——底部标签栏和底部抽屉——被整个锁在 `@media (max-width:760px)` 内部。那个媒体查询有 496 行，占整个文件的 61%

死类三个：`.bottom-nav`（`.tabbar` 改名前的遗留）、`.hero-title`、`.mode-youhuo`。
