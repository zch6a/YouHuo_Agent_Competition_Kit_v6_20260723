# 优活 Agent v6.0：独居老人可信适老生活智能体

> 老人只需开口，优活降低数字办事负担；高风险不猜、不越权，家人只在必要节点接力，每个关键决定都可理解、可核验、可追溯。

1. **可验证复述确认 + 理解度闭环**：付款前老人必须把金额说出来，系统拿它和**权威账单值**比对；说错就指出差在哪里并停下，说不出就再问一次。每次结果按时间衰减加权，累积成这位老人当下的理解度，反过来调节确认强度、语速和选项数量——听错会自动加强，恢复正常又会自动放松；
2. **玻璃盒信任校准卡**：告诉老人系统听到什么、使用了哪些来源、谁决定、能否撤销以及下一步；
3. **安全动作预演**：副作用前显示允许字段、被剥离字段、需要的人工确认和回滚计划。

另外两项在 2026-08-08 这一轮补齐，它们不是新功能而是**把已有能力接到老人的嘴上**：

- **语音可达层**（`care_voice.py`）：用药、健康、日程、亲友和适老档案此前只有 REST 接口，主链一律回兜底菜单。现在"我今天吃药了吗""我的药还够吃吗""你说慢点"都能直接问；除老人改自己的交互档案外全部只读，有副作用的动作仍走原来的确认链。
- **无忧伴对话连续性**（`companion.py`）：把一轮对话归入 8 个主题，同一主题第二次出现改用承接句，会话上下文只保存主题标签和轮次计数、不保存老人的话。

> 复述确认（teach-back）本身是成熟的医患沟通方法，不是我们发明的。这里特别的地方是把它变成**Agent 副作用之前的机器可验证前置门**：比对对象是权威工具值而不是模型的判断，失败被当作"这一项没听清"来定点重解释，并且每次结果都进入审计链与理解度模型。

## 系统架构

```text
语音 / 文本 / OCR / 设备事件
  → N-best语音共识与紧急预检
  → 受约束语义网关
  → 适老认知负荷治理
  → 办事 / 陪伴 / 安全路由与任务锁
  → 目的绑定策略与安全动作预演
  → Saga、老人确认、家属接力、Schema工具
  → 权威状态核验与完成证明
  → 玻璃盒信任卡、审计、报告和用户数据权利
```

大模型可以理解语言和生成友好表达，但不能直接扣款、泄露陪聊、提交验证码/身份秘密、作医疗诊断或自行宣布任务成功。

### 语义层的两种模式

配置 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` 后，`/v2/chat` 主链进入**模型建议模式**；不配置则保持**离线确定性模式**。`/health` 会如实报告当前处于哪种模式。

无论哪种模式，三条硬规则不变：

1. **确定性关键词分类始终运行，并且是下限。** 模型不可用、熔断或出错时，路由结果与离线模式逐字节一致。
2. **模型可以增加覆盖，不能删减。** 它能识别关键词漏掉的说法（"这个月那张单子我还没弄"），但不能把关键词已识别出的事务悄悄取消；两边读法冲突时**提问澄清，绝不二选一**。
3. **模型给的槽位只是参考。** 只填确定性抽取留下的空位，按字段名记录在 `advisory_fields`，玻璃盒信任卡会把它们标成"待核验"；金额等控制字段永远只能来自权威工具。

风险等级、老人确认、家属接力、工具执行、审计仍然完全在模型之外。

### 语音自然度

朗读文本先经过 `backend/static/speech.js` 规范化再送进合成引擎：`2026-08-09 14:00` 读成"八月九日下午两点"，`126.50元` 读成"一百二十六块五毛"，并按标点分句留出停顿。**这一层与引擎无关**——HarmonyOS Core Speech 拿到原始的 `2026-08-09 14:00` 同样会念错。

可选的离线神经语音（默认关闭，关闭时自动使用浏览器语音）：

```bash
pip install sherpa-onnx
# 下载 vits-melo-tts-zh_en（约160MB），解压到 ASCII 路径
export YOUHUO_TTS_MODEL_DIR=/opt/youhuo-tts/vits-melo-tts-zh_en
```

合成完全在本机进行，不联网、不上传文本；模型不随发布包分发。`GET /v6/speech/voice` 如实报告当前用的是哪一种，老人端右下角也会显示。

## 本轮测试真实发现并修复的问题

1. “提醒我下周去医院复诊”曾被“复诊”错误路由为挂号，现改为显式提醒动作优先；
2. “确认办理缴费 / 取消不要缴费”的冲突候选原只返回对话动作，现保留缴费任务域并继续强制澄清；
3. 同一金额同时来自可信工具和冲突OCR时，旧策略可能因存在可信来源而继续；现只要关键值冲突就剥离字段并要求重新核验；
4. HTTP烟雾测试曾错误假设首次保存档案版本必须为2，已改为验证真实字段和合法版本。
